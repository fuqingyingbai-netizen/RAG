桌面小程序 / 实际仪表盘

一个窗口，管理整套推送。

这就是当前运行的新闻助手。配置、日报内容、来源健康和发送记录都在桌面窗口里，日常可以隐藏到托盘。

01

配置集中在顶部

群名、发送时间、最多条数，以及自动发送和登录启动开关，保存一次后生效。

02

运行状态一眼可见

查看当前发送方式、每天的时间、候选数量和来源健康，知道程序是否就绪。

03

预览内容再发送

日报预览包含标题、发布时间、来源和原文链接，也可以手动采集或复制日报。

04

设置与记录可维护

通过页签管理新闻来源、机器人绑定与发送记录；不用重新开发就能调整日常配置。

汇报页只展示截图；实际控制按钮在 Windows 新闻助手里。

02 / 搭建与发送逻辑

前台很简单，后台有完整流程。

把找新闻、判断新鲜度、记录、整理和发送连成一个可持续运行的流程。技术实现保持轻量，重点投入在运行可靠性上。

01

多源采集

读取 RSS 订阅或网页列表，每小时获取标题、原文链接和发布时间。

02

筛新与去重

只选过去24小时，按标题规则筛选关注主题、降低宣传与零碎消息，并排除重复链接。

03

本地保存

保存新闻、来源状态和发送记录，排除已向该群发过的链接。

04

每日整理

每天10:00，首轮每源最多2条，不足时逐轮补位；有足够合格新闻就选满8条。

05

机器人推送

用加签请求发送一条完整日报，检查接口结果并记录发送状态。

为什么不用登录钉钉？ 发送凭证是机器人的 Webhook 与加签密钥。

程序直接调用钉钉接口；网页汇报本身不联网调用机器人，也不包含发送凭据。

V1.3 已实施｜先覆盖来源，再逐轮补位

首轮每个来源最多2条。日报不足8条时，从未选中的合格新闻中逐轮允许第3条、第4条等，优先让不同来源获得名额。无更新来源不占名额，也不要求每个来源至少提供一条。

补位不放宽过去24小时、质量阈值、去重与已发链接排除。优先模型发布、企业应用、重要商业动态，宣传案例和零碎消息仍降权；全部合格候选不足8条时继续少发。

技术选择与对应职责
技术 / 组件在这个程序里做什么
Python组织采集、筛选、定时任务和发送逻辑。
Requests / Feedparser / BeautifulSoup获取订阅或网页列表，解析标题、链接与日期。
SQLite本地保存新闻与发送状态，支持历史排除和防重复。
Tkinter + Pystray提供桌面配置窗口与系统托盘运行。
HTTPS + HMAC-SHA256调用钉钉机器人接口，生成每次发送的签名。
Windows DPAPI把机器人凭据加密保存，绑定当前 Windows 用户。
PyInstaller把代码与依赖封装为可分发的 Windows EXE。

从需求到可运行程序，分四步搭起来

  1. 明确规则与边界

    确定来源、24 小时范围、每日条数、时间和目标群。

  2. 实现并连接模块

    分别完成采集、筛选、存储、界面与调度，再接入机器人。

  3. 验证正常与异常

    测试加签、去重、失败和超时处理，并在群内真实试发。

  4. 打包并配置运行

    生成 EXE、检查交付包，保存本机配置并开启登录启动。

当前新闻流程不需要接入大模型，也无需另配数据库服务。HTML 汇报页用于展示；实际采集与发送由 Windows 新闻助手执行。

05 / 稳定运行背后的工作

把稳定性，做进每个环节。

使用界面可以简单，真正需要处理的是来源变化、时间、重复消息、网络异常、配置安全和跨电脑交付。

多来源适配与健康检查

兼容订阅与网页列表的不同结构；逐源保存采集结果，区分网站失败和当天没有新消息。

统一时间与新闻新鲜度

按原始发布时间选取过去 24 小时新闻。调度和显示固定使用北京时间，缺失日期的条目跳过。

内容筛选、来源平衡与自动补位

首轮控制单源数量，第二轮从其他合格候选补齐；不为补齐而放宽质量、时间和去重要求。

每日发送预留与状态管理

同一群同一天先预留再发送，避免两个任务同时发日报。桌面与机器人方式共享记录，切换不会自动重复发。

超时与不确定结果处理

接口明确拒绝时可修复重试；网络超时或响应异常时保留待核对，停止自动重发，防止消息已到群却再次推送。

加签发送与凭据保护

每次发送生成时间戳和签名，凭据由 Windows 当前用户加密保存在本机。分发包不携带个人配置和密钥。

桌面界面与后台运行

提供来源设置、日报预览、测试发送和运行记录；托盘运行、登录启动、单实例保护，让日常维护更直接。

独立 EXE 打包与交付

封装运行依赖，不要求使用者安装 Python。完成打包自检，并检查发布包没有夹带本机运行数据。

91项自动化测试通过

验证功能，也验证异常时怎么处理。

覆盖采集和日期解析、筛选、重复发送保护、桌面发送防护、机器人加签、返回结果判断与凭据保存。另已完成新版 EXE 自检和配置界面检查；长期运行可靠性还需持续观察。

新版已支持首轮每源2条和不足时补位；跨标题同事件合并及两类内容各4条的固定配额仍未实现。

06 / 运行条件与推荐方式

锁屏可以，睡眠不行。

机器人接口不依赖钉钉窗口，但执行任务的本地电脑需要保持可运行。下面可切换场景查看。

推荐：固定一台开机联网、不自动睡眠的办公电脑，助手隐藏到托盘运行。无需钉钉客户端登录
切换运行场景 · 仅用于讲解，不改变电脑设置
可以发送

锁屏只影响桌面操作。机器人通过接口发消息，只要电脑不睡眠、有网络、助手仍在运行，就可以执行每日推送。

锁屏 ≠ 睡眠；不需要取消电脑锁屏来运行。
10:00—10:30：补发窗口

到点后暂时无法发送，程序会在窗口内尝试恢复。10:30 后不再自动补发当天日报。

同一群，每天最多一份自动日报

已发送记录会拦截重复执行；结果不确定时先人工核对，避免重发。手动测试可例外重复。

来源不足时，先提示异常

当前至少半数启用来源采集成功且状态有效才发送。多数来源失败会暂停，不能保证每天都有日报。

部署建议：先在固定办公电脑持续观察一周，关注是否准点、重复率、来源可访问性和失败记录。重启后需登录 Windows 才会启动助手；如果未来要求无人登录也持续运行，再将采集与发送迁移到常驻服务器。

其他场景：锁屏、钉钉未登录、托盘运行均可发送；睡眠、关机、助手退出不能执行任务；断网时无法提交消息，且不确定结果不自动重发。
