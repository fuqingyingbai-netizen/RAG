# 多轮问答策略与官方模型验证（2026-11-11）

本次只更新代码到 main，不部署，不修改正式环境模型配置。免费模型接入与原生 Ragas 评测仍由原会话负责。

## 改动

- 每个研究会话新增持久化任务记录：独立问题、对象、维度、格式、用户限制及待确认的问题。只保存用户意图，不把旧回答变成知识证据。
- 简单格式转换和已确认单一对象的常见追问在本地处理；复杂切换仍由模型输出结构化独立问题，再重新检索、回答。完整新问题会重置旧任务。
- 明确比较两个对象后，单数“它”先澄清。切换时补全接口失败，也记录待确认状态，防止下一轮悄悄回到旧对象。已解析的用户任务在生成失败后仍保存。
- 任务与账号、会话、索引和资料范围绑定；资料更新或权限变化会使任务失效。删除对话同步删除任务，过期工作进程不能复活记录。
- 新增 `company_chat_tasks` 表，沿用启动时的 `Base.metadata.create_all` 创建，不改旧表字段。合入另一个会话提交 `28ade46` 的 GLM-4.7-Flash 参数适配；测试通过进程环境使用官方 key，不保存明文密钥。

借鉴 [LlamaIndex condense-plus-context](https://github.com/run-llama/llama_index/blob/main/llama-index-core/llama_index/core/chat_engine/condense_plus_context.py) 的“补全问题→检索→回答”，以及 [LangGraph 会话状态持久化](https://docs.langchain.com/oss/python/langgraph/add-memory) 思路；没有引入额外框架依赖。

## 验证边界

自动回归：`test_company_chat_task.py`、`test_company_memory_routing.py`、`test_company_memory.py`、`test_company_answer_exports.py` 共 **116 项通过**。其中一项连续切换 120 轮，模拟补全模型仅调用 30 次，其余由本地策略处理。这验证流程和调用次数，不能当作真实模型准确率或并发压测成绩。

官方实测：`scripts/manual/check_company_conversation.py` 使用智谱官方 `glm-4.7-flash`，最终轮串行请求、间隔 25 秒、不重试；此前探索轮允许一次重试并完整保留失败。每次检索固定返回三家公司内容不同的合成资料，实际调用官方模型完成补全及流式回答。检查对象、数字、来源文件、格式、歧义澄清和未知值拒答；不测生产知识库召回率，不属于 Ragas 评测。全部尝试保留，重试不抹除首次失败。

最终 12 轮均已尝试，**3 轮达到预期（含 1 轮澄清）**；实际 API 调用 10 次，其中 **7 次 HTTP 429、3 次 HTTP 200**，未重试。200 包含 2 次事实回答和 1 次问题补全。这是会话验收用例通过数，不是通用准确率。其余轮次包含接口失败以及为避免沿用旧对象而主动澄清，不能全部算作模型答错。

实测结果与可复核证据见本目录同名 JSON；原始回答、逐次事件、自动检查 XML 与源码摘要保存在 `work/knowledge-conversation-state-run-20261111/`。**当前不能据此宣布官方免费模型达到稳定回答的验收条件。**

探索实测发现三个缺陷：补全失败后沿用旧对象、比较两个对象后模型仍猜单个对象，以及问收费却补全为查收入；本次已增加确定性保护、常见明确问题的本地解析、字段一致性校验及对应回归用例。仍需在官方模型可用性恢复后补足连续多轮实测；复杂语言理解仍依赖模型，不承诺全部指代都能自动判断。
