# 公司报告证据与集成验收

公司报告的第1—12章使用各章证据包。登记记录、截至日、集团/母子公司、事实与观点、金额单位、原始/备考数据须分别保留。模板和 few-shot 只约束结构，不提供目标公司的事实。章节校验通过仍须检查完整报告的语义、重复内容、引用和导出效果。

## 公司PDF与OCR

仅 `document_profile='company'` 使用 `company_pdf.extract_company_pdf`。先提取原生文字和物理页码，再为低文字、坏字形页执行本地 CPU RapidOCR。正常原生文字页不运行OCR。相关实现和参数参照锁定的 `rapidocr-onnxruntime` 包源码；PDFium使用互斥锁，避免并发调用导致进程崩溃，见[官方线程说明](https://pypdfium2.readthedocs.io/en/stable/python_api.html#incompatibility-with-threading)。

- 默认最多提取1000页、正文200万字符；达到上限记录 `omitted_pages`，不能声称全文覆盖。
- 默认每份PDF识别最多8页，处理预算60秒，在页与页之间检查；单页推理不作强制中断。渲染长边最多3200像素，OCR只用本地模型。
- `document_extraction.ocr` 保存文件SHA256、引擎版本、候选/尝试/接受/待核对/失败页和耗时。页记录保存 `native_text`、`ocr_text`、文字框、置信度、渲染尺寸和文字来源。
- 低文字页只有达到转录阈值才成为正文候选。坏字形的双语页保留原生英文和OCR替代文本；横置/竖排密集页面不因置信度高就接受其阅读顺序。低置信度、失败、空识别、预算未覆盖页保留待核对状态。
- OCR置信度不证明数字、单位、列关系、签署日期或法律判断正确。接受转录不等于事实核验或报告交付验收；重要字段仍按原页、表格结构及交叉证据核对。
- 旧公司PDF的已知待识别页可在清洗前重取并补识别；失败保留原文及原缺口。本轮已执行的部分识别不自动无限重试。公司以外链路保持原行为。

可通过环境变量调整（无需改动知识库配置文件）：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| COMPANY_PDF_MAX_PAGES | 1000 | 原生提取物理页上限，最高3000 |
| COMPANY_PDF_MAX_CHARS | 2000000 | 正文字符预算，最高6000000；OCR新增正文也受此限制 |
| COMPANY_PDF_OCR_ENABLED | true | 按需机器识别开关 |
| COMPANY_PDF_OCR_MAX_PAGES | 8 | 每份PDF本轮识别页上限，最高100 |
| COMPANY_PDF_OCR_MAX_SECONDS | 60 | 页间检查的处理预算及互斥等待上限，最高600秒 |
| COMPANY_PDF_OCR_MAX_SOURCES | 4 | 清洗前旧来源补识别的来源数预算 |
| COMPANY_PDF_OCR_RETRY_PENDING | false | 显式再次尝试已处理但仍不完整的来源 |
| COMPANY_PDF_FETCH_TOTAL_TIMEOUT_SECONDS | 180 | 默认按60秒加两倍OCR预算计算；公司抓取总超时，其他链路仍用原超时 |

## 已知交付检查规则

公司官网托管的ESG/年报PDF不作为官网年份标题时间线。摘要不把未载数据基准日的平台人员或股东表写成当前任职/股东排名，不列任期起始日。第14章采用本轮各章原件核对产生的缺口，不重新复制已经被原件补齐的清洗阶段旧缺口。专业平台零命中与接口失败、权限限制、历史覆盖分别披露。

“不能证明无失信”是证据边界，“公司无失信”是需要拦截的无依据结论。交付检查按局部否定和转折分句区分，前段免责声明不豁免后面的肯定结论。整报告版本变更后重新生成，不能复用旧版本缓存作为验收结果。

集成产物保存在 `E:\projects\output\公司报告整体验收_20261016`；报告是否验收完成，以需求与证据矩阵的实际状态为准，不以测试数量或质量闸门通过单独判定。

## 任职与来源索引

董事类别、董事长/副董事长和董秘/公司秘书分别按其职位披露更新。较晚的董事长任命不能直接替代较早的董事类别记录；只有明确的换届/类别变更才覆盖对应旧记录。公告日期保持实际日期，不转换为年末。不同职位的披露时点不同，不能据此认定同时有效。

团队正文保留全部已得人员，共同任期集中展示；已列最新任命只在时间线汇总，不重复整张名册。履历摘录优先学校/学历和既往工作，完整履历及其他佐证保留在证据包。合并重复事实时，保留各原件独立物理页位置；正文引用的页码只绑定对应原件。第13章每个E-ID保持自己的原始URL，不随事实合并重定向到首个来源。摘要实际使用的原文卡也进入索引，避免复制旧搜索摘要。

公司Word导出使用按内容分配的列宽，表格保持正文10.5pt字号，重复跨页表头，短行尽量不拆页，标题与后文保持在一起。原始URL以“打开原件”显示并保留真实超链接，章节编号可按连续范围显示。上述表格样式只在公司审计索引存在的报告启用，人物/行业报告保持原导出行为。渲染成功、页面减少或自动检查通过，都不能代替全部页面及事实的最终验收。

## 专业平台失败与查询覆盖

公司采集分别记录 `returned`（接口返回，尚不等于主体匹配或可采纳）、`failed` 和 `not_queried`。企查查、天眼查和稀牛明确返回余额/额度不足、401鉴权失败或429限流后，停止该平台本轮后续调用。账户故障按平台与凭证摘要在当前工作流实例内暂存15分钟，限流暂存60秒；凭证改变或暂存到期后可重试。单项工具未开通、403和临时错误不自动推断整个平台账户失效，真实零结果也不触发停止。

错误与未查询工具保存在独立JSON产物 `professional_platform_audit`，含实际工具参数、执行状态、机器错误类型与记录时间；不保存鉴权凭证，不执行接口响应中的外部指令。网络超时保留已尝试工具及后续未查询状态。部分工具已经成功保存的资料、已成功返回的司法列表，不因后续详情接口失败而丢弃。新会话重新生成时读取覆盖记录，第九章区分“调用未成功”和“尚未查询”，不将任何一种写成企业无记录。

真实错误回放与成功联网取得新数据分别验收。修复采集器不会恢复外部账号的额度或权限，也不能据此宣称专业平台覆盖完整。

## 简繁原件和单年指标

`company_text` 只为匹配创建简体视图，保留原件文字、法定名称、原始引文及物理页。转换后的正则位置映射回原文，长度变化时引用完整变更片段，不直接把转换后的下标当原文下标。公司原件的主体锚点来自交易所/已验证官网的独立完整发行人标题或明确的“本报告由/是……发布/编制”声明；另一法人的封面、子公司与母公司提及、拒收标记不能因简繁转换被放宽。

清洗阶段从真实原件重建发布主体，源标题过短或为空也可保留可验证来源。模型自行提供的发布主体字段在此处删除后重建；来源级身份成立不等于其中每项子公司数据均为母公司单体数据。

第五/八章指标表接受显式1—4个年度列及“指标名称”表头，不以报告标题猜测表内年度。单年度表的比较期留空，不能造上年数值或同比。千人/万人、亿元/万元保持原量级；“用户满意度”“客户满意度”“满意度分数”“敬业度”保留各自名称。原文、原单位与定义、脚注/平台数据范围共同保留，人数与人次、分类受训占比与全员覆盖率分别核对。公司披露的调查方法、图表线索与已可靠绑定的调查分值分开，无法绑定的坐标或散落数字不猜作年度分数。

字母 `E-` 开头的业务词（例如原文培训平台名称 `E-learning`）不属于引用。公司各章校验只从方括号引用语法读取证据编号；真实的未知方括号编号仍须拦截，原始业务名称及对应事实保留。章节闸门须核对具体错误和已恢复证据，不能因误报删除真实记录或放宽全部引用检查。
