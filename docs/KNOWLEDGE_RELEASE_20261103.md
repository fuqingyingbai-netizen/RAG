# 知识库玻璃界面与生产整合

本轮以 main 的原格式水印下载为基础，将服务器实际运行的行业 v61、章节检查点、任务阶段和项目建议书分支拉回整合。生产启动页、工作台导航和已本地化的前端依赖一并保留，避免覆盖服务器已有功能。发布清单必须根据最终提交重新生成。

知识库弹窗采用透明玻璃表面、背景虚化与边缘高光；文件和案例采用更沉稳的磨砂卡片。两种主题均保留可读的正文和表单。所有样式限定知识库，尊重减少动画、减少透明度及提高对比度偏好，不对文字应用位移滤镜。参考 [shuding/liquid-glass](https://github.com/shuding/liquid-glass) 和 [dpawlikowski/liquid-glass](https://github.com/dpawlikowski/liquid-glass)，样式为本项目独立实现。

音视频上传的请求预算仅在 `/company-knowledge/uploads` 放宽至 130 MiB；文件本身仍受文档 32 MiB、音视频 128 MiB 限制。Nginx 应为该精确路径设置 `client_max_body_size 130m`，其余上传入口维持原限制。可选环境变量 `COMPANY_KNOWLEDGE_MAX_REQUEST_BYTES` 控制知识库表单请求预算。

## 服务器发布与正在执行的任务

本系统的工作流仍在应用进程内运行。蓝绿实例若共用业务库，会触发旧任务恢复逻辑，不能直接同时启动两份生产应用来宣称无损切换。

先在独立发布目录准备依赖，并通过隔离数据库验证升级。候选版本安装完成前不改变 current。正式切换使用 `deploy/activate-release.py`：

- 要求 root、部署归属标记、固定提交清单、共享 data 链接和独立虚拟环境；对部署、前端及备份分别加互斥锁。
- 要求已验证的 Nginx 写入闸门：检测 `/run/supermew-release-draining.flag` 时拒绝新 POST/PUT/PATCH/DELETE，GET 与已有连接继续执行。标记名称为 `# supermew-release-drain-v1`。
- 等待研究、资料入库、智能助手、知识问答和 HTTP 连接排空；暂停任务保留原状态。未知研究状态也阻止切换。超时移除闸门并保留旧应用运行，不杀任务。
- 排空后备份数据库、业务文件、Milvus 和生产配置，保留原发布目录；仅停止本项目应用与向量容器。
- 原子切换 current，启动并检查加载实例。失败恢复原版本、启动服务并移除闸门；不会自动覆盖业务数据库。

同事通过 SSH 直接访问内部 8010 端口时，应遵守同一维护闸门；Nginx 闸门保护公网入口，无法控制绕过 Nginx 的内部请求。任务排空与短暂应用重启仍是必要步骤，本轮不宣称零停机。

上线后检查实例版本、账号鉴权、八份既有资料保留、项目迁移、原格式带水印下载、玻璃界面和深浅主题。生产配置、SSH 凭据和数据库备份不进入 Git。
