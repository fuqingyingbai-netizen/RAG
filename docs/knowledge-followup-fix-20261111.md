# 追问补全格式错误修复（2026-11-11）

用户复现：首问正常，随后要求“请把所选资料中明确披露的数据整理成表格……”，提示“追问补全服务返回格式异常”。

## 原因与改动

`company_memory.retrieval_question` 把“整理成”等格式要求识别为需要承接历史的追问。即使本轮已明确指定所选资料，也会额外调用补全模型；返回内容无法解析成 `{"query": ...}` 时，整轮在检索前中断。因此首问成功并不能保证该路径正常。

- 已明确指定所选资料，且没有历史指代的完整问题，直接使用原问题检索。
- “它”“继续”“把回答整理成表格”“所选资料中上一个问题的指标”等仍补全历史指代。
- 补全请求启用 JSON object 输出，输出预算从 1100 增至 8192 token，避免思考模型的推理挤占 JSON 输出空间；问题本身仍限 1500 字，原超时限制保留。摘要压缩仍使用普通文本输出。
- 格式不合法、上游权限错误和超时仍显式报错。回答继续从本轮有权访问的资料重新检索，历史回答不作为事实证据。

截图未包含上游原始响应，不能据此确定当次具体属于截断、空内容还是格式漂移。小样本真实模型探测中，旧预算也可能成功；预算提升是防护措施，不是已证实的唯一根因。

## 验证范围

接口回归覆盖首问后发送截图原问题、选中文档过滤、历史追问、摘要与回答模型配置隔离，以及权限不足、超时、无效 JSON、非对象 JSON。直接函数测试覆盖省略主语的格式追问、代码围栏 JSON 和历史引用隔离。

另在独立只读进程调用现有知识库模型，使用虚构“甲公司”对话验证：截图原问题保持不变；“把它的营业收入和客户数量整理成表格，缺失项不要推算”可补全公司、保留约束并输出有效 JSON。没有写入业务表或修改运行中的服务。

本次只合入 main，不部署。Ragas 与回答遗漏、引用归因的评测优化由另一个会话继续。
