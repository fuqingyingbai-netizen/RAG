# 行业研究线路优化计划

行业线路的首要目标是让研究范围、检索证据、章节引用和交付状态一致。先修复事实解析和范围变更后的缓存复用，再改进检索与报告质量，最后优化速度和诊断。

开发分支：`feat/industry-report-optimization`。分析基于 `main` 提交 `a8f773a7f62758c02a6cc23eff371375bcd87c48`，日期为 2026 年 10 月 14 日。本次建立分支并提交计划，业务修复按下面的顺序实施。

## 分工和代码范围

行业专属文件是 `backend/research_strategies/industry.py` 和 `backend/report_agents/industry_report_agent.py`。建议新增行业范围、事实校验、评分与交付检查模块，把行业规则逐步从公共工作流中移出。

`backend/research_workflow.py`、`backend/report_agents/report_prompts.py`、`backend/research_schemas.py`、`backend/research_api.py` 和前端由三条线路共用。公共改动单独提交，注明影响范围，并运行公司、人物和行业的隔离回归。公司和人物专属策略及报告 Agent 保持各自负责人维护。

## 已确认的问题

| 优先级 | 问题和影响 | 代码依据 | 修复方向 |
| --- | --- | --- | --- |
| P0 | 公共 JSON 解析器先搜索任意位置的 Markdown 代码围栏。合法 JSON 的事实字符串包含代码块时，会被误判为解析失败；索引函数随后把整个 JSON 当成一条事实，削弱后续检索。 | `research_workflow.py` 的 `_plain_json`、`_index_cleaned_facts` | 优先直接解析完整 JSON，仅在整个输出被外层围栏包裹时剥离围栏。解析失败记录明确诊断，不将完整事实库静默当成一条事实。 |
| P0 | 缓存指纹只包含类型、对象名称和关联机构，没有行业范围。更改赛道、地域、截止日或用途可能复用旧事实和报告；非人物项目的来源匹配检查直接返回 true。 | `_intake_evidence_fingerprint`、`_project_sources_match_intake`、`run` 中的复用判断 | 行业专用指纹纳入规范化范围、启用模块、重点公司和策略版本；按变更影响失效检索、清洗、评分和报告缓存。历史产物保留版本。 |
| P1 | 后端支持 `industry_focus`、`research_purpose`、`include_capital_markets`、`as_of_date`，前端创建、新运行、续跑和二阶段请求没有完整传递。 | `research_schemas.py` 的 `ResearchRunRequest`，`frontend/script.js` 的各运行入口 | 增加行业专属表单和统一请求组装，保存、回显、续跑均使用同一范围。区分研究截止日与任务交付日期。 |
| P1 | 赛道识别只有平台经济、即时零售、云服务、AI 应用、数字化出海等固定映射；查询硬编码美团、阿里、京东、腾讯、字节和 CNNIC；范围卡固定排除硬件制造和电信基础设施。机械制造、生物医药等行业可能偏题。 | `_resolve_industry_scope`、`_prepend_industry_scope_card`、`industry.py` 的模板 | 显式用户范围优先，通用模板为基础，行业配置补充专业关键词、权威源与样本企业；不自动排除未确认的领域。 |
| P1 | 资本市场开关与实际检索不一致。`capital_market=none` 时仍加入融资和上市查询，只在报告 Agent 跳过第 8 章。融资年报查询又可能先被分类为代表企业。 | `IndustryResearchStrategy.expand_search_queries`、`BaseResearchStrategy.expand_search_queries`、`IndustryReportAgent.generate` | 明确一级融资、IPO 与二级交易指标各自开关语义；过滤不启用查询和章节任务。行业查询显式设置证据范围，避免依靠关键词顺序误分类；保留权威路由元数据。 |
| P1 | 第 8 章标题未命中行业章节范围规则，落入只接受行业层和赛道层的默认分支。离线输入一条 `capital_market` 事实，该章证据包得到 0 条。 | `report_prompts.py` 的 `industry_chapter_scopes` | 使用行业专属章节配置，以稳定章节标识映射允许的证据范围和模块，避免依赖标题关键词。 |
| P1 | 章节从摘要开始按 URL 全局互斥分配，每章最多 8 条；摘要可能抢占实体章节来源。同一报告中的不同事实不能分别支持不同章节。每章不足 3 条时又直接变成提示，可能丢弃有价值的一手事实。 | `IndustryReportAgent.generate`、`_focused_cleaned_json` | 实体章节先分配相关事实，摘要和综合评估引用其成果；按事实编号去重，允许同一来源支持不同事实与章节。稀疏章节保留真实事实和适用边界。 |
| P1 | 行业评分提供了事实 E-ID，但输出不要求有效 E-ID，也没有公司线路的评分证据验证。数值的地域、期间、单位和统计口径主要靠提示词控制；规则清洗默认 `scope_match=in_scope`。 | `assess_risk`、`_risk_evidence_payload`、行业事实标注和规则清洗分支 | 每个评分维度绑定有效且适用的证据编号，无证据返回 unknown；建立数值口径和范围校验。样本企业事实与行业整体判断分开。 |
| P1 | 质量闸门主要统计标题、长度、URL 和引用章节，缺少行业数值口径、引文支持、越界结论的实质检查。相同的无证据提示也可能被判为重复正文。闸门失败可保存待复核稿，而前端完成数量只看任务 completed。 | `_validate_delivery_report`、报告保存分支、前端 `readyCount` | 结构化记录章节证据覆盖和校验结果；区分正式候选稿、待复核稿及导出失败。允许有边界的缺证提示，禁止以空章节或链接数量代替内容质量。 |

上述 JSON、资本查询、第 8 章筛选和范围指纹问题已使用离线最小输入复现。其余为源码确认的规则缺陷及其可能影响；尚未触发新的在线行业研究来测量实际产物。

上次华为测试走的是公司线路。专业平台鉴权失败、模型超时、内容审核拒绝和缺少 Word 渲染环境可以作为公共能力改进线索，不能当成行业线路已发生的测试结果。

## 实施顺序和验收

### 第一阶段 修复事实解析和范围缓存

- 单独修复公共 JSON 解析器，覆盖普通 JSON、外层代码围栏、字符串内部代码块、空值和非法 JSON。
- 行业指纹包含赛道、地域、截止日、用途、重点公司、启用模块和策略版本，说明各字段对应的失效阶段。
- 验收：合法事实条数不因代码围栏变成一条；改变行业范围后不复用不适用的事实、评分或报告；公司和人物原有类型分派保持一致。

### 第二阶段 打通行业研究范围

- 建立行业范围数据结构，支持纳入与排除赛道、地域、截止日、用途、代表企业和资本市场范围。
- 严格校验日期与布尔值；默认假设在提交预览中可见，范围变化可追踪。
- 前端创建、新运行、续跑与二阶段统一组装行业参数，后端规范化结果持续保存。
- 验收：用户输入经保存和续跑保持一致；硬件行业不会被默认排除；研究截止日与交付日期独立。

### 第三阶段 改进行业检索

- 删除互联网专用的通用默认查询，按行业配置加载专业术语、统计与监管源以及用户指定企业。
- 查询直接携带模块、证据范围、赛道、地域和时间约束；尽可能调用检索源原生过滤，后续再核验数据期和适用范围。
- 按有效证据缺口补充检索，设置模块查询预算、补搜轮次和总时限；来源抓取失败与整条任务失败分别记录。
- 验收：半导体、生物医药、新能源设备和互联网样例不互相混入无关默认企业；资本开关语义在计划、执行与报告中一致；模块质量按可用证据计算。

### 第四阶段 完善事实口径和行业评分

- 数值事实保存指标、值、单位、币种、地域、细分赛道、统计期间、预测属性、口径和来源定位；不兼容数字分开呈现。
- 区分行业层、赛道层、代表企业和资本市场证据；缺失范围标记为待核验，不能默认合格。
- 评分引用有效 E-ID，校验取值范围和证据适用性。unknown 的理由与评分一致；风险分和行业吸引力等不同评分分别定义。
- 验收：不同地域、期间或子赛道不会被直接合计；无证据维度没有确定评分；单个企业处罚不能自动推导全行业风险。

### 第五阶段 重做章节证据分配和交付检查

- 建立行业章节专属映射，优先完成实体章节，再生成摘要和综合评估；第 8 章正确接收资本证据。
- 正文事实引用 E-ID，来源章节和台账使用同一分配结果，缺证事项集中到后续研究清单。
- 总编调整后重新校验引文、章节和数值；实质缺陷输出待复核稿及可操作原因。
- 前端区分生成完成和可交付状态；导出诊断区分 DOCX 成功、视觉检查未执行和导出失败。
- 验收：摘要不抢占实体章节证据；来源索引与正文引用一致；15 章结构保留，关闭或缺证的章节有准确说明；待复核稿不会被显示为已通过质量检查。

### 第六阶段 回归和运行效率

- 建立行业专属离线测试，公共改动同时回归三种类型的策略、JSON 解析、事实筛选和报告导出。
- 使用模拟模型输出覆盖超时、审核拒绝、无结果、单章失败和恢复路径；真实调用控制预算并在实际功能验证时执行。
- 以各行业样例记录检索耗时、有效事实率、章节证据覆盖、未知评分比例、模型调用量与交付结果。以实测结果决定查询并发和证据预算。
- 工作流保留连续事件和摘要，前端展示最后活动时间，便于区分长任务与卡住。

## 项目 67 实测后的第二轮修复

2026-10-14 的人工智能行业任务暴露了原文片段挤占结构化事实、风险引用未进入章节证据包、关闭资本模块仍参与检查和评分、全文润色超时，以及 NUL 入库和索引状态未回写的问题。

清洗版本升级为 `industry-evidence-v3-structured-cards`，报告版本为 `industry-report-evidence-v8-validated-cards`。章节优先采用同模块的结构化事实和数值口径已校验事实；来源分数从已归档来源继承。风险综合章节带入实际底层证据，其他章节只收到适用于本章的风险内容。章节证据包只筛选一次，并以完整 JSON 控制输入预算，来源索引列出正文实际引用的证据。

数值校验使用指标值和单位，允许明确等价的金额单位、千分位和小数格式；不能因为同一原文中出现过某个数字就视为该数字已核验。口径缺失数值明确标注待核验；不允许其用于行业合计或评分。关闭资本模块时不再产生该模块的权威来源缺口、风险维度或必做补采建议；真正缺证的启用维度仍返回 unknown。

取消全文重写，改为章节校验、一次局部修复和目录合并。行业章节默认超时 90 秒，修复 45 秒，SDK 不隐藏重试；修复失败保留可追溯的输入事实摘录。公共入库清除实际 NUL 字符并保留字面转义文本。索引在产物提交后启动，独立 SQL 会话回写结果；超时不覆盖已完成结果。行业支持 `POST /research/artifacts/{artifact_id}/reindex` 单独重试，校验项目访问权及产物类型，拒绝仍在执行的索引，替换仅限该项目该事实版本的向量记录。Embedding 数量不一致明确失败。

项目 67 的原始事实和章节输出进行离线回放，不调用模型或搜索、不更新原项目。失败局部修复走事实摘录保底后，保留 16 章、33 个引用来源，章节包中包含 16 张已校验数值卡，交付检查通过。此结果只验证证据传递、检查和降级路径；实际模型的新生成质量与耗时仍需真实任务确认。私人测试材料保存在被忽略的 `work/`，不发布到 GitHub。

前端提供去重后的章节问题清单、索引状态与数量、单独重试入口。LibreOffice 尚未安装，Word 文件可正常导出，但页面级版式预览仍未执行。其他行业和地域的配置继续由实际样例完善。

## 项目 68 实测后的第三轮修复

第二轮任务完成了 16 章报告，自动交付检查通过，索引 880 条记录并成功回写。仍存在三个清洗请求连续超时、摘要修复超时和商业化评分缺证的问题。源码与实际资料回放进一步确认：风险证据 JSON 约 7.9 万字符，评分提示词直接裁剪到 3 万字符；摘要的完整章节正文包含了摘要证据预算之外的编号。这些输入问题不能通过放宽评分或引用检查解决。

行业清洗升级为 `industry-evidence-v4-bounded-cleaning`：单请求默认 60 秒、无 SDK 隐藏重试；每批共享 150 秒与最多 3 次调用预算，默认只拆分一层。预算耗尽保留规则事实和已完成的子批结果，记录未完成片段及调用次数。其他线路继续使用原模型路线。行业精洗按模块选择含实际数值、订阅、按量计费等商业模式内容的来源，并在长文中保留相关原文窗口与开头的主体/日期信息，不仅裁剪网页前部。非连续片段有明确标记，不拼接成新的事实。

报告升级为 `industry-report-evidence-v9-grounded-summary`：摘要只复用实体章节实际引用、且仍在摘要预算内的事实；按章节均衡选取并去重，模型看到的摘要提示和证据包使用相同编号。摘要修复失败保留最多 5 项可追溯事实，显示需人工复核的说明。章节降级单独写入产物元数据，前端可查看具体章节与原因，不再仅由自动质量检查通过掩盖综合写作降级。

评分证据按模块优先结构化事实，输出完整 JSON，预算不超过 2.8 万字符。批次信息缺口明确作为待核验线索，不能代表全库没有数据；商业化无适用证据仍返回 unknown，不以企业个案替代行业整体评分。数值验证补充万亿元/万亿美元及等价单位，防止这些金额绕过数值口径检查。

新增 13 个离线回归覆盖超时预算、拆分调用上限、其他批次保留、公司路线隔离、评分 JSON 完整性、摘要编号一致性、降级说明、晚出现的商业化原文与万亿单位。行业专项 65 项通过；扩大离线回归 145 项通过，原有 5 项公司/人物相关失败未变化。前端参数回归通过。第二轮原始资料离线回放不调用模型、不写数据库：16 章与交付检查保留，评分 JSON 约 2.7 万字符，摘要保底 5 项事实，章节证据包含 14 张通过数值校验的卡片。

## 第三轮实测后的第四轮优化

项目 67、68 的第三轮均完成，但精洗分别出现 48/47 次请求超时，16/15 批退回来源摘录。两个产物的结构化标记数为 0，其中项目 68 实际还有 3 条模型提取事实未设置该标记；数值口径检查通过数仍为 0。商业化维度 unknown，总风险分为空。章节生成成功，摘要正文却超过 600 字目标，自动检查仍将产物标为候选终稿。

清洗升级为 `industry-evidence-v5-source-grounded`，报告升级为 `industry-report-evidence-v10-bounded-summary`。新增从存储的正文抽取连续原文句子的行业规则路径，不使用搜索摘要补数值。数值卡仅在同一句明确提供行业主体、指标、数值、单位、地域、统计期和口径时通过字段检查；缺字段、多个地域或数据期仍为待核验。原文句子和 URL 保留，多个指标分别编号。定性商业模式句子不再因同一页面其他位置有数值而被整体禁用评分。企业年报、招股书和已标记的企业样本继续保持企业边界，不用其直接证明行业整体风险。

行业模型请求移除人物身份、隐私及企业尽调字段，每批最多 3 条短事实，输出预算 2000 tokens。连续失败达到默认 6 次后停止本轮追加精洗请求，已完成子批和原文规则事实保留；计数在每轮重置。原来的每批时间、调用次数限制继续有效，并修正结束批次的预算耗尽记录。成功模型事实必须能把原文引文定位到存储正文，再统一设置结构化标记；不匹配的引文不进入正式事实卡。

商业模式查询分为行业研究与企业年报两类，不再因“收入结构”一词将行业查询全部标为企业样本；增加行业商业化权威检索路线。范围策略版本升为 `industry-scope-v3`，避免旧查询标签和产物被当作新规则的结果继续复用。旧企业样本不会在离线回放或数据库中被改为行业证据，商业化缺证仍保持 unknown。

摘要在加入数值待核验标记后实际检查 600 字上限，仅允许一次压缩修复；仍超限时采用短事实摘要，并记录生成降级。交付检查加入摘要超限及市场规模章只有未核验数值的检查，保存待复核稿。前端显示事实质量计数，区分 Word 文件完整性与页面版式检查。行业报告/建议书导出增加 ZIP、必需 XML 和非空正文检查；缺少 LibreOffice 时仍显示版式未校验，不将文件结构通过当成页面排版通过。

新增 18 项回归。行业专项累计 83 项通过；扩大离线回归 156 项通过，保留原有 5 项公司/人物测试失败。前端参数回归通过。第三轮项目 68 正文离线回放，不调用模型或搜索、不写原项目数据库：提取 70 张口径字段完整的数值卡，其中 40 张进入章节证据包；16 章、43 个引用来源、279 字事实摘要和 Word 文件结构检查通过，交付检查无报错。回放故意让旧章节修复失败，用于验证事实摘录降级与引用契约，不代表新模型写作质量或实际商业化评分已经通过。来源统计本身的真实性、商业化检索的新覆盖以及页面排版仍需后续真实任务验证。

单条真实模型抽取验证未执行：自动审批阻止将数据库中保存的来源片段发送到配置的外部模型主机，需用户明确授权内容和目的地后再验证。本轮的模型超时改善仅经模拟预算与请求格式测试，不能据此宣称线上模型响应耗时已经改善。
