# 公司前端与章节 Agent 契约

前端选项、研究问题、工具路由和写作职责统一存放在 `backend/company_chapters.json`。前端通过 `GET /research/company-chapters` 读取目录，不再维护独立的十三模块列表。

每次报告创建十四个有独立编号的章节 Agent。第 2—11 章负责各自的正文；第 1、12 章负责摘要及综合评估；第 13、14 章负责实际引用索引和后续研究点。确定性表格、数值核对和实际引用索引继续由程序计算。模型精编、格式修复和逐章审稿调用绑定对应 Agent 的职责及模板版本。十四个职责不代表同时发送十四次模型请求，精编仍按既有工作池限流。

前端展示第 1—12 章。第 1、12 章标为自动汇总，其余十章默认勾选。勾选控制重点研究深度，未勾选章依靠已有资料整理并保留缺证边界，十四节目录始终保留。显式空勾选不会回退为全部研究。基础身份和真实经营的原有交付门槛继续适用；新模式下勾选章节也进入必答项核查，缺证不能标记交付成功。

每个重点选项只对应一个 `company.chNN`、一份单章节 requirement 和一个 `company_chapter_NN_agent`。基础检索、下一轮补证和交付补证保持相同归属，专业平台也按选中章节的已实现路由调用；天眼查主体搜索和司法文书下钻作为相应工具的必要步骤保留。平台原件可能为多个章节提供材料，记录其请求用途不代表事实已获接纳。现有主体、原文、数字、期间、引用和独立审稿规则继续执行。

| 章 | 模板标题所在单元格 | 内容要求 | 表达示例 |
| --- | --- | --- | --- |
| 1—4 | A2、A3、A4、A5 | 对应 B 列 | C3、C4 |
| 5—8 | A9、A14、A16、A17 | 对应 B 列 | C16 隔离 |

| 13—14 | A26、A27 | 对应 B 列 | 无 |

配置保留工作簿 SHA256、工作表名和单元格位置。第七章 C16 实际为供应商、采购及经销话题，保留原文供审阅，禁止进入写作提示词。第 2、3、9 章示例仅用于表达方式，提示词明确禁止将其中主体、数值或“无风险”结论当作本次事实。

只读核对：

```powershell
python scripts/import_company_template.py '模板绝对路径.xlsx' --check
```

维护人员审阅模板变化后，可用 `--write` 刷新标题、内容要求、示例及来源指纹。工具不修改工作簿，不自动改写研究问题、路由或专业规则。第七章示例的主题问题需人工审阅后再解除隔离。修改注册表会改变契约版本，旧页面提交过期版本时返回 409 并要求重新加载目录。

## 所有公司任务的逐章流程

新建任务、恢复及二阶段请求统一采用 `company-chapter-flow-v1`，保留 `company_template_version` 和规范章节 ID。旧标签只在入口转换为章节 ID，不启动旧公司流程。用户已清理旧任务，本次不删除历史记录。人物、行业功能保持各自的入口。

第 2—11 章依次运行：查本地资料 → 定位并核对本章原文 → 核对模板问题 → 如有缺口，文件内扩大一次 → 必要时执行本章基础检索 → 合并具体缺口补查一轮 → 本章编写、独立审稿与检查点 → 下一章。未勾选的章节只使用本地资料，不发外部补查。第 12 章综合评估、第 1 章摘要及第 13—14 章汇总在正文完成后生成。

程序保留原文，建立标题、物理页码、段落偏移和内容哈希索引；初版不创建文档向量。已有的主体、期间、单位、原句校验和专业表格解析器继续执行。候选段落并不等于已核事实：模型只能选择可追溯原文窗口，再由现有校验器核对。文件内扩展只读本章候选，不能把“未命中”解释为没有发生。问题覆盖检查记录 answered/partial/missing/conflict/not_applicable，并检查证据 ID；指定必答章的问题尚未全部核对时输出待复核稿。

后续章节取得新资料后，汇总前比较各章依赖的原文哈希，仅重新核对受影响的章节，不开启新的外部搜索轮次。相同 URL 已有正文时跳过下载；仅有检索摘要或抓取失败时允许重新取正文。新查询仍可能返回已知 URL，这与重复下载不同。完全相同且成功的搜索请求按目标、范围和实际请求参数复用；平台请求按供应商、工具及实参复用。部分引擎失败、欠费、鉴权失败或空响应状态不明的请求不冒充成功缓存。

报告元数据记录模板版本、十四个章节 Agent、问题覆盖、逐章状态、阅读范围、逻辑模型调用次数、输入字符、供应商返回的 token、搜索查询数、平台请求数、缓存命中数和耗时。服务端 SDK 自身的 HTTP 重试不等同于新的逻辑模型调用；本地定位字符数不能直接换算成节省的 token 或费用。

## 检查点、预算与清理

任务检查点位于 `projects/{id}/company_chapter_flow/`。恢复前核对范围、模板版本和状态文件哈希；单章正文复用还要检查原文依赖、信息用途和独立审稿回执。暂停、预算耗尽和失败保留资料；预算耗尽不算通过。

初始整份任务额度较高，后续根据实验调整：

| 环境变量 | 默认额度 |
| --- | --- |
| `COMPANY_FLOW_MAX_MODEL_CALLS` | 500 次逻辑模型调用 |
| `COMPANY_FLOW_MAX_INPUT_CHARS` | 24,000,000 输入字符 |
| `COMPANY_FLOW_MAX_SEARCH_QUERIES` | 600 次多引擎搜索查询 |
| `COMPANY_FLOW_MAX_PLATFORM_REQUESTS` | 500 次平台工具请求 |
| `COMPANY_FLOW_MAX_SECONDS` | 14,400 秒累计运行时间 |

只有正文交付门槛、Word 导出、实际渲染与布局检查均通过，才清理临时下载正文、服务器上传副本和检查点。报告、建议书、最终引用、原句证据台账和最终展示附件保留。不会删除用户桌面的源文件。清理失败单独记录 `cleanup_pending`，再次运行只重试清理，不重新研究。待复核稿、渲染失败和未完成任务均保留临时资料。

## 验证

### 2026-11-04 正文校验调整

- 编辑回执升级为 `company-editorial-v4-semantic-review`。引用编号、记录归属、金额单位及完整输出继续检查；日期和近义转述不按字面差异直接退回写作，由独立审稿核对实际含义、日期及状态。
- 已知原句片段 ID 由程序绑定保存的真实原文，不要求审稿模型逐字重抄。模型上报的不同措辞另留记录；正文摘录只允许恢复空白差异的位置，不用语义相似度伪造原文或正文定位。未知 ID 仍不放行。
- 原文数字未在正文逐字出现，只形成给审稿模型的提示，不再以“所有数字必须保留”机械拦截。关键金额、比例、期间、否定及条件遗漏仍由模型明确判未通过；数值/单位实际改写的程序约束保留。
- 定位记录有误或审稿调用失败时，仅重试审稿并保留原正文；状态区分 `review_incomplete`、`review_record_incomplete` 与 `revision_required`。失败批次草稿仍存于检查点，不作为已通过正文使用。
- 同章已通过批次的段落继续呈现，未审完批次不再让整章回退到模板。章稿附未完成说明，正式交付门槛仍要求全部必要核验及全篇一致性审稿完成。
- v3 已通过回执须原文、决定、目标及旧输入哈希一致，并通过 v4 当前校验，才迁移复用；不把旧通过标记直接当作新通过凭据。
