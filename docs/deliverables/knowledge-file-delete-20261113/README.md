# 粘贴文件删除修复与验收（2026-11-13）

## 问题与修改

线上最近两次用户删除请求均为 HTTP 200；对应文件均为 `deleted`，且各有一条有效回收站记录。因此这两次是删除成功后页面反馈不及时，并非原件删除失败。未据此推断所有失败都是前端问题，另外测试了服务异常、权限和并发分支。

| 问题 | 修改后的行为 |
| --- | --- |
| 删除成功后仍等完整目录刷新，缺少成功提示 | 收到服务器明确的 `deleted: true` 后立即移除该行，提示“已移入回收站”，目录和统计后台刷新；旧请求通过修改序号校验，不能把已删除行重新放回列表 |
| 确认框和请求期间可重复触发 | 同一文件从确认框开始防重复；请求中显示“删除中”，禁用重复入口；取消或失败释放状态 |
| 成功响应丢失后重试得到 404 | 已删除文件在重新检查访问和管理权限后返回成功，不重复建回收站记录，也不延长原来的十天期限 |
| 先提交 `deleting` 状态释放锁，云端失败后残留中间状态，并发请求可能冲突 | 删除操作在同一数据库事务持有锁；云端确认成功后才提交删除和回收站记录。超时、限流和云端异常不提交本地删除，提示重试；并发更新返回可重试的 409 |
| 排队状态一概不能删除 | 未领取、没有云端注册和索引任务的新副本可取消入队并删除。已注册云文件的重试队列、上传、解析、索引中和有效工作租约继续保护，明确提示“本次未删除” |
| 手动刷新仍同步等待云端全量目录，网页实测超过三十秒 | `local_only=true` 的手动刷新先返回本地最新目录，强制云端同步后台进行，同一知识库只保留一个同步任务 |
| 自动轮询在目录加载中又排队下一轮全量刷新 | 正在加载时跳过自动轮询；保留真实复制、删除等变更触发的补刷新，避免慢网络下刷新连续排队 |

删除只把文件放入十天回收站；共享原件仍有其他文件、历史版本或笔记附件引用时不能物理清理。没有改变资料权限边界和模型配置。

## 测试范围

本地共通过 **45 项不同的后端测试、109 项前端测试**，重复执行的测试不重复计数。后端删除专项最终为 18 项，其余为复制、移动、回收站、目录和项目删除回归。

| 场景 | 验证内容 | 结果 |
| --- | --- | --- |
| 复制与剪切 | 单文件复制、同名副本、独立索引、剪切移动整个版本系列、重复请求、目标权限和部门边界 | PASS |
| 刚粘贴即删除 | 未领取的排队副本可删除；稍后投递的入库任务不会重新处理它；已完成复制请求不能把已删副本复活 | PASS |
| 常规和异常状态删除 | 可检索、失败、归档、历史残留 deleting 状态删除；当前及旧索引 ID 均限定在所选文件 | PASS |
| 处理中删除 | 上传、解析、建索引、有效租约、已有任务的排队重试、已有云端注册的排队重试拒绝删除并保留原件 | PASS |
| 重试与并发 | 丢失响应后重试、重复点击、两个删除同时发生、删除与修改同时发生、一条有效回收站记录、原到期时间不变 | PASS |
| 云端故障 | 超时、HTTP 429、HTTP 500、HTTP 200 但业务失败；不泄露上游正文，不留下新的 deleting 状态 | PASS |
| 权限 | 其他可读用户无管理权限、不可读资料、不存在文件、已删文件重试仍重新校验权限；线上匿名请求 | PASS |
| 共享原件与回收站 | 删除或到期清理一个副本不损坏其他文件；最后引用才可回收；笔记附件引用保护；十天内恢复、重建索引和再删除 | PASS |
| 版本与整树操作 | 最新版删除不重新暴露旧版；完整历史、恢复版本；项目及目录整树删除恢复保持边界 | PASS |
| 前端错误与时序 | 取消、服务拒绝、网络断开、响应格式错误、切换账号、过期目录响应；未确认成功前不移除文件 | PASS |
| 手动刷新 | 慢云端不阻塞本地目录，强制刷新有效，重复刷新合并为一个后台任务 | PASS |

PostgreSQL 验收使用线上数据库的隔离恢复副本和独立原件目录，屏蔽外网；验证真实事务锁、并发请求、清理引用锁、权限和恢复。没有在生产资料上模拟限流或物理清理到期文件。

前端旧版的两个问题也用同一测试复现：删除成功但目录未刷新时旧行仍在、网络断开后直接显示原始错误。见 `baseline-ui-failure.txt`。新版本相应用例通过。

## 线上验证与发布证据

最终运行代码：`723e673b9c32685de41a001bb88e52191b7ac5ac`（后端与已验收的 a52915e 完全相同，最后补丁只修改轮询前端）。实际激活回执、备份位置、实例号和线上验收以本目录的 `final-activation.log`、`final-live-setup.json` 和 `live-verification.json` 为准。

网页验收使用独立的合成私有项目，执行真实右键复制、粘贴、取消删除、确认删除、重复删除、原件访问、回收站恢复后重建索引和再次删除，并核对公网静态文件哈希、进程工作目录、发布清单与配置哈希。测试项目最终进入正常回收站，不提前清理其原件。

首次网页实测发现手动刷新等待超过三十秒，因此增加云端后台同步修复。随后查明轮询会在目录加载中继续排队，使慢网络下全量刷新连续执行，最后补上加载中跳过自动轮询。前一版正常网页刷新实测 25.91 秒；最后轮询补丁的浏览器复测为 12.08 秒，9 页各请求一次，无自动轮询重复排队；这是两次实际公网观测，不作为严格的同条件性能基准。最初隔离脚本对“其他用户”的预期由公共可读文件改为受限测试文件；首次粘贴反馈脚本也增加等待网络请求进入拦截阶段，避免把网络调度误判为产品失败。最后验收结果单独记录，不将这些初次脚本结果计作通过。

发布仅覆盖知识库后端文件和对应前端资源，后端发布保留 494 份其他运行文件，最后前端补丁保留 496 份其他运行文件。先等待在途任务退出，再备份数据库和配置，切换服务并校验；没有改动模型、原件存储和其他业务模块。

真实百炼测试中，一份副本返回 `PARSE_FAILED`；该失败副本仍可正常删除、原文件仍可读取。另一份已就绪副本完成网页删除、回收站恢复、新云文件重新索引成功、再次删除的完整验收。这次云端解析失败单独保留为外部服务观察项，不算作已根治的解析稳定性问题。

## 边界

正在实际处理的文件仍需等待任务结束再删除；不强行中断云端解析。全量目录刷新仍需翻页读取；本次最终公网刷新为 12.08 秒，删除确认后的行移除不等待它。第三方服务持续不可用时，删除会明确失败并允许重试，不承诺云服务永不报错。并发和云端异常主要在隔离环境验证；未做生产高并发压测，也未重跑 Ragas。源码回滚不能恢复已经删除的数据库行，资料恢复使用回收站或数据库备份。
