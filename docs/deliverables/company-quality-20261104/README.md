# 公司报告四项质量修复与真实回放

本轮按四项要求修改公司报告链路，并用此前失败的海天、金山原件回放。证据来自独立工作区和独立数据库，原始主工作区、旧实验数据库及运行服务没有被修改。

| 要求 | 已实现的行为 | 验证依据 |
| --- | --- | --- |
| 放宽程序拦截 | 删除正文、摘要和旧归纳入口的数字、单位、币种、日期、评级及内容词表拒收规则；取消程序改写数字的调用。语义正确与否交给独立审稿，引用 ID、原件哈希、偏移及结构校验继续保留。 | 海天 `273.99 亿` 换行 `元` 可以自然写成 `273.99亿元`；实际模型独立审稿接纳。错误金额、来源归因、日期仍可被独立审稿拒绝。 |
| 修复缓存与错误段落定位 | 实际提示、规则实现和模型配置参与回执指纹，变化后重新审稿；意见绑定所有相关段落 ID，再回连信息 ID。格式修复保留有效意见和原始未定位意见，不能用“通过”抹掉失败记录。 | 海天相同输入复跑调用 0 次；仅修改实际审稿提示后重新调用 4 次。多段意见定向改两个批次，无关章节复用。摘要及组装段落也有稳定 ID。 |
| 对齐全文与片段语境 | 写作、逐批审稿和最终审稿携带同源证据包；小原件提供完整正文，大原件明确标为局部可见并保留相邻原文及表头候选的精确偏移。阅读 ACK 与当前可见全文分开。 | 表头单位、跨页及断行回归通过。原件变化使旧回执失效；阅读完成与候选记录格式未完成分别记录。 |
| 禁止程序加空话 | 摘要回退只排版已核事实卡原句；移除自动“事件记载”、通用免责段、空图谱说明、缺项矩阵和 75 行空清单。无评分的规则保留在元数据中。 | 实际已核数值、事件和原文公式保留；缺失字段仅来自具体模型核对。待复核原因保留在元数据和导出封面，正文审稿完成后不再追加通用提示而破坏审稿哈希；空章节不算重复正文。保存后核对数据库、对象正文及 Word OOXML。 |

真实运行还暴露并修复了几处问题：章节号返回为“1. 摘要”及摘要段落编号编造时，只有正文中的唯一精确引句可以恢复定位；来源修复返回部分结果时，已有效的修复继续保留，其余原始记录保持待处理。续跑保留已解决的摘要和段落反馈，规则变化仍须重新审稿。最终全文审稿默认最多四轮修改，可配置到八轮；本次真实验证采用八轮上限。内容不再变化时停止，继续受整个任务的调用预算约束。

意见定位到具体段落后，只重写出错段落，其他段落原样保留；合并后重新审稿全部相关信息。如果新的独立审稿否定某个保留段落，则取消该段落的保留，不能拿旧的通过回执强行通过。同一审稿意见跨越多个写作批次时，将相关批次联合修复；允许用一段话保留多条重复原文的所有支持 ID，合并后仍逐条核对全部原始事实。未涉及的批次继续复用。联合批次的原问题分类和回执一并保存，相同输入续跑不再拆回旧批次。可选章节缺数据保留在诊断中，不再要求添加空矩阵才能验收。信息路由使用独立身份，允许把财务信息从工商章节移到对应章节；独立审稿不再套用章节作者的表达示例和写作约束。路由规则实现、实际审查提示和模型配置同时绑定逐项判定、断点日志和整章复用检查。转出记录的用途判定独立保存，不因原章节正文为空而丢掉缓存；重新归属时，旧接收章节及旧队列定向失效，原始事实和可复验的旧审稿回执继续保留。队列中的同一原文仅改变用途说明时，不覆盖目标章节已审回执，也不误报原文冲突；原文、目标章节或用途分类冲突仍拒绝合并。独立审稿精确定位到另一条重叠原文时，只修复遗漏的支持 ID，正文原句保持不变，并重新独立审稿。

GitHub 参考已核对到固定提交：LangChain 的提示和模型配置缓存键、LlamaIndex 的细粒度引用节点。仅借鉴设计方式，没有引入框架或复制源码；许可证与文件哈希见 [参考记录](github-reference-audit.json)。
