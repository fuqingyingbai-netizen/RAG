# 公司知识工作台

## 2026-11-10 总资料库与部门归属

顶部保持知识库首页、总资料库、智能问答、经验沉淀四个入口，原资料分类和个人工作入口继续沿用。公司知识库侧栏增加市场部、项目部、制度文件、专家资料，进入同一资料库的对应部门范围；不新增公共资料库，也不复制原文件。

项目与文件新增固定 `department` 字段：`market`（市场部）、`project`（项目部）、`policy`（制度文件）、`expert`（专家资料）。空值表示历史待归类，与自定义标签分别保存。部门只负责归档分类，不改变内部／机密、指定成员、创建者与管理员的既有权限。

从部门入口创建项目或上传独立文件时默认带入当前部门；从总库创建或上传新资料必须选择归属。项目下的目录与文件自动继承项目部门，包括新版本、发布的图文笔记和旧客户端按项目名归档的资料。项目负责人可在项目设置调整归属，所有下属版本一同更新；独立文件通过文件设置归类。移动到其他项目时继承目标项目部门，确认窗口展示前后归属；移动回根目录时保留原归属。原件、预览、下载和回收站保留原有处理流程。

总览增加部门筛选和待归类选项，可与现有资料分类组合；进入项目或子目录后不重复显示部门筛选。侧栏分类计数跟随当前部门，顶部总资料数仍汇总整个资料库。部门提问通过后端 `/selection` 解析当前可读、已完成索引的文件 ID，范围为空时拒绝，不扩展到全库；继续沿用最多 1000 份及资料库／经验沉淀分离的规则。返回资料位置会恢复部门、目录、筛选和选择状态。

启动时仅增量添加项目与文件的部门列，历史归属保持空值，原权限与文件内容不变；重复启动兼容。旧 API 客户端未传部门时仍可工作，新表单明确传入空部门时拒绝新建普通项目或独立资料；失败重传与既有项目的历史待归类状态继续兼容。

验证：`python -m pytest test/test_knowledge_departments.py -q`、`node --test test/knowledge-departments.test.cjs`。`python scripts/check-knowledge-departments-ui.py --artifacts <隔离验收目录>` 使用真实前端、真实知识库接口与一次性数据，替换云端和回答提供者，覆盖部门导航、创建、子目录上传、限定范围问答及返回、水印副本下载、只读项目和手机布局，不访问业务数据库。

## 2026-11-06 独立知识库模型

回答生成、追问补全和长对话摘要统一读取 `COMPANY_KNOWLEDGE_MODEL`、`COMPANY_KNOWLEDGE_BASE_URL`、`COMPANY_KNOWLEDGE_API_KEY`。2026-11-09 实测原 `glm-5.2` 通道超时后，生产知识库已切为同一中转站 `https://llm.goaichat.top/v1` 的 `glm-5.3-flash`，密钥只保存在受保护的环境配置中。文档解析、索引、检索和重排继续使用 `BAILIAN_KNOWLEDGE_*`。创建背调任务及其全局模型配置保持不变。

三项独立配置必须同时填写；部分填写时报配置错误，不能悄悄切回其他服务。兼容未配置独立模型的旧部署：优先使用完整的全局模型三项，再使用百炼 Agent 模型。推理不再分别选择两个服务。补全调用的权限、连接和格式错误会显示为服务错误；只有模型明确返回对象不明时，才要求用户补充对象。补全与摘要的单次总超时为 90 秒，生成的读取超时为 120 秒，会话总时限为 330 秒，低于写入租约的 360 秒。

GLM-5.3-Flash 不发送关闭思考参数，使用 `reasoning_effort: low` 控制延迟；推理内容不作为回答展示。模型名替换后必须验证普通和流式请求，不能把通道故障视为未接入中转站。GLM-5.2 兼容请求使用 `thinking: {type: disabled}`，而非 Qwen 的 `enable_thinking` 字段，避免非预期的长思考占用回复和 JSON 补全预算。该参数仅对已验证支持的 GLM-5.2 启用，不套用于强制思考的 GLM-5.3。参数依据：[智谱思考模式文档](https://docs.bigmodel.cn/cn/guide/capabilities/thinking-mode)。

## 2026-11-03 知识工作区与案例库

导航为研究首页、资料库、研究问答、案例库。查找历史案例先进入案例库浏览项目、关键词或标签；比较资料结论先进入资料库，明确勾选至少两份可检索资料后，再进入研究问答确认问题，不自动发送。方法与模板保留原分类及历史数据，移至案例库导航下，与项目经验、案例复盘和培训分享共同归集。

上传与管理增加自定义标签和文字说明。每份资料最多 20 个标签，每个 1 至 40 字；去除前后空格并按原顺序去重。上传者与管理员可以修改项目、行业、分类、复核状态、等级、授权、标签和说明。受限资料的标签和说明不返回无权阅读的账号。资料库支持标签及上传时间/更新时间筛选，日期起止包含所选日期，以浏览器本地日历为准；未记录该时间的资料不进入限定日期结果。

保密等级和权限是两个不同维度。主表单保留保密等级，并展示对应的阅读规则；内部资料默认成员共享，可勾选“内部资料也单独授权”；保密等级仅有内部、机密两类，机密仅管理员可用。原有受限内部资料在编辑时保持受限，不能因表单简化自动公开。指定成员和权限申请/审批仅适用于内部资料。

音频支持 MP3、WAV、M4A、OGG、FLAC，视频支持 MP4、WebM，单个最多 128 MiB；文档与图片仍最多 32 MiB。格式头进行基本校验，实际播放依赖浏览器对内部编码的支持，无法解码时可下载原件。音视频必须填写文字说明。原件保存在受控存储，通过认证接口读取为浏览器 Blob 后播放，离开阅读器释放 URL，不公开静态路径。

音视频本体不上传百炼、不自动转写；入库工作器上传独立 Markdown 说明，包含文件名、项目、行业、标签与人工描述，再由原检索链路提供引用。回答须说明依据为文字说明，不能声称听过录音或观看过视频。修改这些说明字段时，先将旧索引从本地问答范围移除，排队清理旧云端索引并重新索引；失败可重试，原件与版本保持不变，处理中需完成后再修改说明。资料属性更新仍会使依赖该资料的旧会话内容失效。

数据库启动时增量增加 tags、description、stale_cloud_id，保留已有目录和原件；首次应用后端改动需要重启服务。四个页面采用独立样式 company-knowledge-universe.css，完整设计与验收说明见 [知识库界面设计](COMPANY_KNOWLEDGE_DESIGN.md)。

定向验证：`node --test test/company-knowledge-ui.test.cjs test/knowledge-request-lifecycle.test.cjs`；`python -m pytest test/test_company_workspace.py test/test_company_knowledge.py test/test_company_memory.py -q`。浏览器隔离验收脚本为 `scripts/check-knowledge-studio-ui.py`，使用生产前端、缓存 Vue/Element Plus 依赖、合成 API 和可解码音视频，覆盖入口、组合筛选、属性编辑、上传与播放，以及桌面/手机布局；不连接真实百炼或业务数据库。

员工在本系统完成上传、分类、阅读与提问。百炼承担文档解析（含扫描件 OCR）、切分、索引、检索与模型推理；不重复导入本地 Milvus。本系统保存原件和权限目录，将通过权限校验的片段交给模型生成答案。

```env

BAILIAN_KNOWLEDGE_AGENT_ID=your_published_chat_agent_id
BAILIAN_KNOWLEDGE_INDEX_ID=your_knowledge_index_id
BAILIAN_KNOWLEDGE_CATEGORY_ID=default
COMPANY_KNOWLEDGE_MODEL=glm-5.3-flash
COMPANY_KNOWLEDGE_BASE_URL=https://llm.goaichat.top/v1
COMPANY_KNOWLEDGE_API_KEY=your_knowledge_model_key
COMPANY_KNOWLEDGE_USERS=employee_username_1,employee_username_2
COMPANY_KNOWLEDGE_OBJECT_STORE=local
COMPANY_KNOWLEDGE_LOCAL_STORE=E:/persistent-data/company-knowledge
COMPANY_KNOWLEDGE_BUCKET=company-knowledge
```

原件默认位于项目 `data/company_knowledge`，通过认证接口读取，不暴露为静态目录。worktree 建议使用持久化绝对路径，避免清理代码时带走资料。可设 `COMPANY_KNOWLEDGE_OBJECT_STORE=minio`，使用现有 `MINIO_ENDPOINT`、`MINIO_ACCESS_KEY`、`MINIO_SECRET_KEY`、`MINIO_SECURE`；原件专用桶由 `COMPANY_KNOWLEDGE_BUCKET` 指定。原件和数据库需同时备份，已有资料时不要直接切换存储配置。

沿用 `scripts/start-local.ps1 -Background` 启动。数据库初始化新增 `company_documents` 表，不修改既有研究表。未完成任务会在重启后恢复扫描。

## 已实现功能

- 表格资料库：按项目、行业、分类、处理状态、复核状态筛选；收藏按当前账号保存在浏览器。
- 批量上传：支持 PDF、DOC/DOCX、XLS/XLSX、PPT/PPTX、TXT/MD、JPG/JPEG/PNG，每个文件最大 32 MiB。Word、PDF、图片使用智能文档解析，其他格式自动选择解析器。
- 同上传者、项目和文件名下，相同内容返回重复提示；不同内容作为新版本保留。旧版本独立展示和授权，也参与检索，比较时需选择对应版本。
- 状态：等待、上传、解析/OCR、建立索引、可检索、失败。浏览器每 6 秒刷新，只有文件状态 FINISH 才视为可检索。
- 原件阅读：本系统上传的 PDF、DOC/DOCX、XLS/XLSX、PPT/PPTX 通过服务端分页预览连续阅读，图片直接预览，TXT/MD 按原文编码显示。首次 Office 转换使用 LibreOffice，按原件 SHA256 缓存版式和有限页数，每次交付仍校验权限并添加个人水印；下载保留原格式。解析文字不保证保留原件版式。历史资料没有受控原件时暂不提供下载。
- 全部资料或勾选项目、目录或最多 1000 份已完成索引的文件提问（目录包含下级）；阅读区可围绕原件提问。范围变化开始新对话。
- 上传者和管理员可管理分类、复核状态及可见范围，重试失败任务或删除资料。处理中的资料需等待完成后删除。

## 权限与问答路径

正常账号注册后即可使用知识库，已有普通账号也默认可用；旧 `knowledge_access` 开关和 `COMPANY_KNOWLEDGE_USERS` 不再限制入口。普通账号仅能读取、创建和管理内部资料，机密仅管理员可用，创建人和旧授权名单不能绕过等级限制。机密资料不会返回普通账号的目录、项目统计、预览、搜索、下载、问答及历史引用。内部资料继续支持 `members`（正常账号共享）及 `restricted`（创建人、管理员、指定系统账号）；单独授权的内部资料仍可申请审批。旧字段保留兼容，不需批量改写账号或文件数据。项目/行业用于分类，不等同于项目权限组。详见 [账号管理说明](ACCOUNT_MANAGEMENT.md)。

目录、原件、预览、问答均在后端校验。后端计算可访问的云端文件 ID，传递 `search_filters: [{doc_id: [...]}]` 给百炼检索，再校验每个返回片段的文件 ID 和知识库 ID。提问中明确出现可访问资料的项目或行业完整标签时，先在相应目录范围检索；项目标签无需出现在正文中。检索显式设置 rerank_top_n=20，避免默认只返回五条片段；生成证据先保留不同文件，再限制同文件片段数量，防止大量表格行挤掉其他文件。空范围或无命中直接说明“当前资料中未找到依据”，绝不退回不受限的全库问答。

原云端问答接口没有公开的逐请求文件范围参数，因此采用：受权限约束的云端检索 → 后端校验证据 → 模型流式生成。回答、追问补全和摘要共用上述独立知识库模型配置，兼容回退顺序见本页首节。提示词在后端统一管理，保留引用、资料不足、冲突和待复核说明。控制台的其他 Agent 工具规划/策略不参与此路径；只修改控制台提示词不会修改本系统提示词。

### 检索完成后生成失败

如果已经出现引用片段，随后生成阶段报认证错误，应分别检查检索服务和回答模型。旧版本把回答模型接口的 HTTP 401、403、404 也显示为百炼错误，不能仅凭提示判断百炼密钥失效。新版本在项目模型调用失败时显示“回答模型”，百炼调用失败时显示“百炼”。

服务器生产配置位于 `/etc/supermew/app.env`。更换兼容接口时，成套更新 `BASE_URL`、`ARK_API_KEY` 和 `MODEL`；`BASE_URL` 以 `/v1` 结尾，代码会追加 `/chat/completions`。密钥必须由对应接口提供，模型 ID 需在该接口可用。`BAILIAN_KNOWLEDGE_*` 继续用于文档解析与检索，不能替换成第三方模型接口或密钥。

更新前备份配置，确认没有正在运行的研究任务，保留文件 `root:supermew`、`0640` 权限，运行生产配置检查并重启 `supermew`。随后验证版本接口，再用已授权资料进行一次问答验收。仅修改本地 `.env` 不会改变服务器配置。只切换知识库时修改 `COMPANY_KNOWLEDGE_*` 模型三项，不修改影响创建背调任务的全局模型变量；百炼仍需保留解析、索引与检索权限。

仅用户问题用于承接对话，历史助手回答不再作为模型上下文，避免范围变化或权限撤销后带入旧证据。SSE 展示连接、检索、生成及用时，每 3 秒空闲发送心跳；断开时取消生成，不暴露模型内部推理。引用按文件 ID 合并，片段保留独立编号。

历史云端资料首次同步默认共享，管理员可调整权限；带本系统上传标签的未知文件不会被自动归类成共享资料。权限目录必须与云端索引一并保留。百炼管理权限/API Key 持有人仍可访问云端资源，应用权限不替代云账号治理。旧版无范围问答实例应下线后，再上传真实受限资料。

## 任务恢复与删除

保存原件和元信息 → 上传租约 → 预签名 PUT → addFile 注册 → 指定 DATA_CENTER_FILE 和 docIds 提交索引 → 查询每份文件状态。API Key 不发往 OSS，前端不接收密钥、租约或存储路径。

云端文件 ID、任务 ID 分阶段持久化。正常重试复用已注册文件；任务超时则继续查询原任务。数据库租约避免重复领取，启动后每 8 秒扫描可接管任务。注册成功但本地 ID 尚未写回时进程崩溃，仍存在不确定窗口，管理员需核对云端孤立文件，系统不盲目公开未知文件。

删除先从本系统可检索范围移除，再删除指定知识库中的文件和切片；云端失败可再次删除重试。不删除其他知识库或数据中心文件。本系统保留不可再通过 API 访问的原件恢复副本，运维需另行管理保留周期。

## 下载水印与操作留痕

所有知识库下载均由后端生成当前账号专属的副本，保留服务器原始归档文件与原件 SHA256，RAG 继续读取原件。PDF 每页加可见水印；DOCX 在各节的默认、首页和偶数页页眉添加浮动个人水印，PPTX 在每页添加水印图形，XLSX 添加工作表背景水印和每页打印页脚身份标记，保留原格式、正文、单元格、公式和现有页眉页脚。旧版 DOC/XLS/PPT 使用 LibreOffice 兼容处理后仍返回原扩展名；TXT/MD 保留原格式和原正文编码、字节，在首尾添加身份文字；JPG/JPEG/PNG 生成带水印 PNG；录音统一生成带首尾身份提示的 MP3；视频统一生成烧录可见水印的 MP4。标记包含登录账号、UTC 时间与追踪编号，下载副本的哈希和追踪编号写入操作记录。音视频的格式、编码与录音首尾时长会随导出发生变化。

`GET /company-knowledge/documents/{id}/download` 为正式下载入口。旧 `/original`（包括 download=false）同样只能返回带标记副本；PDF 页面预览也带个人标记。引用及已保存会话不再返回可绕过此流程的云端原件链接。历史资料未归档受控原件时不能下载，转换失败、超时、缺少依赖时也不会返回无标记原件。完成转换后再次检查文件权限，防止处理期间被撤销权限后仍导出。单进程最多同时生成两个副本，处理繁忙返回 429，可手动稍后重试；前端不会自动重试下载。

普通账号可以管理自己创建的项目和所属目录，不能修改其他人的项目；管理员可管理全部。项目创建者 `created_by`、文件实际上传者 `uploaded_by`/`uploaded_by_user_id`、最后修改者 `modified_by` 均由认证账号在后端填写，前端不能指定或覆盖。项目 owner 与文件归属仍表示业务所有者，管理员代上传时会与实际上传人不同。新增字段对旧资料留空，界面显示“历史未采集”，不补造操作记录。

创建项目、上传文件、修改项目/文件/目录、继承项目属性、删除、重试、权限审批、导出与失败，写入 `company_audit_events`。属性修改的记录与业务修改处于同一数据库事务，保存字段的前后值、操作人 ID/账号和时间。`GET /company-knowledge/audit-events` 支持 project_id、document_id、page、page_size；管理员可以查看全部，本项目/文件管理者只能查看对应范围，项目范围还会排除其无权阅读文件的记录。API 没有修改或删除操作记录的入口。这是本轮的基础留痕，尚未扩展回收站、版本恢复或定期复核。

### 转换环境

Python 依赖随 `pyproject.toml` / `uv.lock` 安装，新增 ReportLab；FFmpeg 优先使用系统或指定程序，否则使用 imageio-ffmpeg。DOCX/XLSX/PPTX 下载标记不依赖 LibreOffice；Office 在线分页预览和旧版 DOC/XLS/PPT 下载需要 LibreOffice。Linux 部署建议安装中文字体、espeak-ng 和旧版兼容处理工具，例如 Debian/Ubuntu：

```sh
sudo apt-get install --no-install-recommends libreoffice-writer libreoffice-calc libreoffice-impress fonts-noto-cjk espeak-ng ffmpeg
```

可选配置：`COMPANY_KNOWLEDGE_OFFICE_BINARY`（soffice；Windows 建议 soffice.com）、`COMPANY_KNOWLEDGE_WATERMARK_FONT`（中文字体文件）、`COMPANY_KNOWLEDGE_FFMPEG_BINARY`、`COMPANY_KNOWLEDGE_SPEECH_BINARY`（Linux）。Windows 录音身份提示使用 System.Speech。旧版 Office 的兼容转换使用临时用户配置并禁用文档宏，临时文件在转换结束后清理；生产运行账号应继续使用服务专用的低权限账号。

导出限制：纯文字最多 2 MB，PDF 最多 1000 页，图片/页面图层最多 4000 万像素，音视频副本最多 512 MB。超出限制时要求拆分，保持失败时不返回原件的规则。

长文档导出在单次请求内按页面尺寸复用个人水印图层和 PDF 图像对象，避免每页重新栅格化与嵌入同一水印；不同账号/不同下载不共享水印副本。前端为下载附带独立 request_id，通过 `/documents/{id}/export-status` 查看兼容处理、水印处理、整理与完成阶段（PDF/PPT 为页，Word/Excel 为处理项），并显示已等待时间。进度只在当前进程保留 15 分钟，不存文件内容，按当前账号与文件权限检查，同一 request_id 重复提交返回 409。读取进度不重新启动导出，成功、失败或超时都会释放前端下载状态。

验收：`python -m pytest test/test_company_watermark.py test/test_company_workspace.py`；配置 Office 路径后执行旧版兼容和渲染用例，并核对水印、副本播放、权限与原件不变。旧版格式发布时必须具备兼容处理依赖，否则对应格式按上述规则拒绝；现代 Office 文件仍可原格式下载。

文档与图片继续自动解析/OCR、建立 RAG 索引；单份 32 MB。录音/视频单份 128 MB，没有说明时以“已归档”状态保存，只播放与下载；填写说明后将人工说明作为独立文本建立索引。不自动转写或分析音视频内容。移除说明时先清除旧说明索引，再回到归档状态。

相同项目中不同子目录允许同名文件。相同目录内相同内容提示重复，内容不同创建新版本。文件原件的对象存储键不随目录/文件名变化。历史原件与现有问答权限过滤继续生效。

升级增加 company_projects、company_folders 及文档的 knowledge_project_id/folder_id/inherits_project 字段；旧的全项目同名唯一索引改为目录维度唯一索引。旧资料按知识库、上传者和项目名称建立项目 ID，空项目名归入“未归档资料”，保留旧属性与文件 ACL，不迁移或复制原件字节。重复执行不产生重复项目。项目更名同步目录内资料的项目名称；项目属性变化后需要的音视频说明会重新索引，正在处理时拒绝冲突编辑。

2026-11-09 兼容修复：保留线上项目列表、悬停详情及其配套样式，发布按成套组件/样式校验；空笔记和仅标题笔记在前端禁用发布并给出填写提示，后端仍以 422 校验防绕过。有内容的笔记按保存草稿→发布快照→索引完成执行。权限申请由所有启用管理员共享审批，页面定时刷新待审批数量，不发送邮件或短信。

## 预览异常处理（2026-11-10）

PDFium 的密码错误独立映射为 `X-Preview-Error: pdf_encrypted`，损坏文件为 `pdf_invalid`；需要打开密码的文件明确提示解除密码后上传，不尝试猜测或保存密码。归档缺失使用 `original_missing`，历史无原件资料提供管理者补传入口；POST `/documents/{id}/original` 需管理权限、资料确认和格式/体积校验。原子保存成功后清除旧 cloud_id、job_id 并安排重新索引，保留资料编号、归档位置和ACL；索引未就绪不返回旧片段。

大XLSX（超过一万行、256列或20万单元格）通过 GET `/documents/{id}/sheet` 按工作表及50行/40列窗口提供受权限保护的数据预览。跳过前置行时使用流式XML解析，只将所选窗口交给openpyxl解码；日期和单元格类型沿用原样，公式显示原式。原件不改写，图表、图片和打印版式仍以原件为准，小表继续走原分页PDF预览。每次返回检查最新ACL和源哈希并记录个人追踪信息；解析/问答就绪状态与本地原件预览状态独立。

转换超时会终止该转换的整个子进程组，避免LibreOffice启动器退出后残留soffice进程。
