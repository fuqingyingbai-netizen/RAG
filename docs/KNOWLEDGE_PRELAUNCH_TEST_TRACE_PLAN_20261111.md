## 5 隔离环境与样本数据

### 5.1 环境必须真正隔离

- 独立PostgreSQL数据库或实例、Redis命名空间、原件存储目录或bucket前缀、百炼测试index/agent及云文件前缀；验证每个外部写入目标。
- 使用脱敏数据恢复时，复制原件及相关元数据、版本关系；重新映射用户、ACL、会话、文件标识。仅复制数据库、不复制原件或云索引会造成伪故障。
- 真实模型可使用现有服务，但密钥通过受限配置注入，知识库归档/解析/删除必须指向测试资源，不能复用生产云index。
- 不复制生产密码、token、签名下载链接、客户信息或未脱敏历史问答；脱敏后再建索引。测试账号采用新的凭据。
- 启动、迁移、目录同步、过期清理及后台恢复本身可能写入。运行前核实配置目标，后台清理不能指向生产存储。
- 测试程序先核对显式测试标记、环境名和目标允许列表；默认拒绝未知地址。拒绝启动的保护用例也要实测。
- 只有同配置而资源不同；如果CPU、内存、存储、网络、云端配额与线上不同，在性能报告中写明，不能直接承诺线上容量。

### 5.2 账号与目录样本

至少准备：管理员；项目创建者A；另一个普通成员B；已授权读者；未授权读者；停用账号；已归档账号；匿名请求。每类角色至少一组不同账号和独立浏览器上下文。

覆盖四个部门、待归类、资料库和经验沉淀；准备共享项目、受限项目、机密资料、根目录独立文件、三级以上目录和同级分支；文件规模超过一页，并准备20/100/101/1000/1001份选择范围测试。

现有测试规则中显式资料上限为1000，检索批次为每100份、最多3批并发；最终候选需要复核这些实际限制。大批量边界验证可使用本地合成记录和受控替身检验过滤集合，另用真实云索引验证多批次，不为了凑数量重复付费索引1001份敏感原件。

### 5.3 文件和答案样本

文件集包括普通与扫描PDF、加密PDF、损坏PDF、DOC/DOCX、PPT/PPTX、XLS/XLSX、TXT/MD、图片、图文笔记和音视频说明；覆盖空文件、扩展名伪装、中文与超长文件名、同名同内容、同名不同内容、多版本、原件缺失及不完整云解析。

Excel样本包含用户提供的四表模板、隐藏行列、合并单元格、富文本、公式无缓存、大表首尾分页、复杂图表降级和解压尺寸上限。读取前后核对原件SHA-256。按路由、请求体中间件和代理的最小实际限制测试，不只看单个常量：源码普通上传32MiB、音视频128MiB，而代理示例为52m，必须先对照实际部署并记录有效上限；未协调前不能宣称128MiB端到端可传。

答案金标准使用无敏感的虚构公司，设置不同单位、年份、相近名称、相互冲突的版本、缺失项、跨文件汇总、长文后半段证据及明确禁止推算的表格问题。每个问题保存人工确认的应有事实、不能出现的事实和支持片段。

| --- | --- | --- |
| 数据越权 | A替换项目、文件、目录、note、asset、session、message、回收项ID访问B私有资源；覆盖列表、原件、缩略图、sheet、引用与导出 | 内容、元数据、计数和对象都不越权；拒绝响应无隐私泄漏；无写入副作用 |

## 8 完整链路模型和最小实现

### 8.1 必须关联的四种链

```text
用户操作 interaction_id
  ├─ 页面并行请求 request_id A → trace_id A
  ├─ 页面并行请求 request_id B → trace_id B
  └─ 问答HTTP请求 → 认证 → 范围/ACL → 会话/追问补全
                    → 云检索批次 → 证据选择 → 模型流 → 保存/提交 → SSE终态

上传HTTP请求 → 原件保存 → 文件记录/事务提交 → 返回接收结果
  └─ 持久后台任务 job_id / originating_trace_id
       → 排队 → 工作租约 → 上传凭证 → OSS PUT → 云注册 → 索引任务
       → 状态轮询 → 检查点/提交 → ready / failed / archived
       └─ 重启后恢复的新执行 trace，通过link关联原任务
```

浏览器一次操作可能触发多个独立请求，不能靠伪造相同HTTP request_id强行合并。每个请求独立编号，用interaction_id归组。后台任务不占用已经结束的HTTP父span；同进程及时执行可承接上下文，跨进程或重启使用持久job与span link。

### 8.2 实现选择

先复查是否已有内部平台。没有时，优先使用OpenTelemetry的trace/span和上下文能力，手工补业务阶段，并通过独立本地导出器输出有界、可轮转的结构化JSONL。若已有可用Collector则接入OTLP，但周五前不把部署一整套新监控集群作为前提。

自动HTTP/SQL埋点与手工业务埋点明确各自职责，不能重复记录同一层耗时。锁定兼容版本，在隔离环境证明线程、异步、SSE和后台任务完整再推广；不能只安装依赖便称“链路完成”。

最外层采用兼容ASGI流式发送的计时方式，覆盖进入路由前的413、鉴权失败、校验失败和未处理异常；流直到最后一个响应body或断开才结束。日志采用标准模块/文件输出，不把技术日志塞回业务数据库，避免数据库坏了反而无日志或递归记录。

实施前给出文件改动清单。建议新增一个统一观测模块与测试工具，不在几十个函数里散落重复计时与字符串日志。共享数据库引擎的观测必须测试相邻业务，不重构其业务规则。

## 9 统一记录字段与时间口径

### 9.1 编号和公共字段

| 字段 | 用途与要求 |
| --- | --- |
| timestamp | UTC ISO8601含毫秒；报告展示北京时间。用单调时钟计算耗时，不能用跨主机墙钟相减 |
| environment service instance release_sha | 区分隔离/线上、服务实例与确切版本；前端错误另带资源版本 |
| interaction_id request_id trace_id span_id parent_span_id | 分别标识用户操作、单次HTTP和阶段父子关系。符合W3C的trace_id/span_id；校验外部传入值，限制长度，不能信任其身份信息 |
| event_name stage component operation | 固定可聚合名称，例如request.completed、db.query、kb.retrieve_batch；不能把问题正文或文件名放进span名 |
| actor_id role | 仅经服务端认证后填入最小标识；匿名或认证失败保留匿名；不采信请求中的角色声明 |
| project_id document_id version session_id job_id | 按需记录技术标识与版本；不用完整文件名、正文和会话内容替代 |
| business_request_id watermark_trace_id provider_request_id | 关联已有会话幂等号、水印和上游诊断号；字段缺失为null，不能混为新观测trace_id |
| start end duration_ms outcome | 毫秒数值，区分success、rejected、failed、cancelled、partial及unknown；记录是否已发送、是否实际调用 |
| error_category error_code exception_type safe_message | 使用稳定分类，信息脱敏且限长；保留cause层级与上游状态，不能只记“服务异常” |
| attempt retry_reason backoff_ms timeout_stage | 每次真实尝试单独记录；不修改既有重试语义来美化指标 |
| telemetry_status | 标记正常、丢弃、缺失或中断；未测量必须null并注明原因，不能填0 |

每个知识库HTTP请求100%有请求摘要，每个实际DB操作、外部HTTP尝试和关键业务阶段有详细记录。初期小规模按100%详细采集设计；任何采样、限额或降级产生的缺口都计数并可见，不能宣称错误被完整保留却采用会提前丢弃错误请求的头部采样。

公共响应尽量返回服务端request_id与trace_id；SSE首个控制事件也带可关联编号。跨域需要只暴露必要头，错误响应同样有编号。客户端编号仅用于关联，不参与授权。不要将用户ID、资料元数据等放入向第三方传播的baggage。

### 9.2 浏览器与反向代理的关联

前端请求封装生成interaction_id，记录操作开始、请求发出、响应头、业务完成/失败、用户取消、内容可用及前端异常；只记录固定操作名、版本、技术编号和脱敏错误，不上传页面文本、表单内容或文件名。需要持久化的前端诊断采用受鉴权、有限流、限字段和限请求体的内部遥测入口，或复用已有等价入口；不能只留在用户关闭页面即消失的console。新增遥测入口纳入接口总账和安全用例。

浏览器Resource Timing跨源字段受限时标记不可用，不能以0表示没有网络耗时。下载大文件、SSE答案和上传索引的用户可见完成时间分别定义，不把点击后发送成功当作完成。刷新/账号切换后的旧请求仍可查，但不得污染新账号的操作上下文。

对实际启用的Nginx或等价代理，配置脱敏结构化access/error日志，关联服务端返回编号和代理请求编号，记录request_time、upstream_connect_time、upstream_header_time、upstream_response_time、status、upstream_status和字节数。代理拒绝的413、连接失败502、读取超时504也必须有记录；缺失应用trace时用代理编号查询，不能要求根本没进入应用的请求有DB span。

实际代理头部由受信任网关生成/校验，外部同名头不能冒充真实用户或覆盖安全归属；不用未经处理的request_uri、referer和Authorization作为日志内容。代理若发生多次上游尝试，保留每次时长和状态，不把数组值当单次耗时。记录生效配置和代理版本，不能只修改仓库示例便宣称线上已启用。

### 9.3 耗时必须分别定义

| 指标 | 开始与结束 | 不能混淆的事项 |
| --- | --- | --- |
| browser_action_ms | 用户操作至内容真正可用/失败可见 | 包含浏览器等待；不能等同后端耗时 |
| server_request_ms | ASGI接收至最后响应发送或断开 | SSE/下载必须覆盖响应体，不能在返回响应头时停止 |
| application_first_answer_ms | 后端收到问答至首个answer_delta | heartbeat、progress、SSE头不算答案首字 |
| provider_first_answer_ms | 模型请求发出至首个有效答案增量 | 独立于检索/追问补全耗时；reasoning内容不冒充答案 |
| stream_total_ms | 请求开始至业务完成/明确失败/取消 | HTTP200不是成功终态 |
| http_headers_ms / http_body_ms | 外部请求开始至收到响应头；响应头至body读完/断开 | HTTPX response hook发生在读取body之前，不能当全请求结束 |
| queue_wait_ms | 入队至获得执行机会 | 与实际上传/解析执行区分，后台长任务另算总时长 |
| db_acquire_ms / db_query_ms | 开始申请连接至取得连接；SQL游标执行开始至结束 | checkout事件不是完整排队起点；SQL时间不包含所有fetch/ORM/事务 |
| db_fetch_ms / orm_materialize_ms | 拉取结果和生成业务对象的受控业务区间 | 无法精确拆开时合并明确命名，不能凭差值伪造 |
| db_flush_ms / db_commit_ms / db_rollback_ms | 实际flush、提交、回滚调用前后 | SQL已执行不代表事务提交成功 |
| parse_preview_ms / file_io_ms | 受控解析/渲染/文件读写开始至结束 | 原件读、转换、加水印、传输不能统称“数据库慢” |

并行span耗时之和可能大于请求总耗时；用起止区间的并集解释等待和自身耗时，不能简单相减或宣称所有阶段相加必然等于总耗时。未归因区间显示为unattributed，超过请求时长10%且大于100ms时进一步定位。

网络DNS、TCP、TLS、连接池等待按当前HTTPX/httpcore支持的trace事件采集。DNS未单独暴露时只报告connect合并时间；复用连接标记reused且不伪造本次TLS耗时。第三方内部查询耗时未公开时标记provider_internal_unavailable。

## 10 HTTP与云服务的埋点要求

覆盖百炼cloud_rpc、云文件列表、上传凭证、OSS上传、addFile、索引创建及状态查询、检索每一批、模型配置读取、回答模型、历史摘要、追问补全、云文档片段读取及实际使用的存储HTTP客户端。

每次外部调用保存：provider别名、脱敏host、method、路径模板、attempt、发送状态、连接复用、连接/头/body/总耗时、状态码、业务code、上游request-id、字节数、超时配置、错误类型和是否重试。URL查询参数、签名、凭证及完整请求响应体默认不记录。OSS签名URL仅保留允许的主机及路径类别，禁止原样落盘。

分别测试：DNS/连接/TLS失败，连接池超时，读/写超时，401、402、403、404、429、5xx，200但success=false或业务code失败，无效JSON/缺字段，SSE中的error、空答案、提前结束、连接被重置、取消和客户端断开。分类不能把上游鉴权失败等同本系统用户未登录，也不能将上游错误转换成“当前资料未找到依据”。

SSE必须记录终态：completed、upstream_error、invalid_response、incomplete_stream、client_cancelled、permission_revoked、save_failed或process_interrupted。已有error事件必须与日志中的错误编号关联。只有答案完整且要求的保存成功才记completed；推送过文字但保存失败属于partial或save_failed，不能只按HTTP200统计成功。

观测不能为读取body而提前消费整个流，不能改变首字时间、心跳、断流检测、流量回压和取消行为。证明开启埋点后每个成功/失败路径只记录一次终态，异常/取消也关闭连接，不泄露后台任务。

## 11 数据库查询写入与事务的完整记录

### 11.1 查询和写入

对所有实际SQLAlchemy引擎注册观测，包括账号与知识库共用引擎、后台SessionLocal，以及当前实现确实创建的其他连接。用SQLAlchemy执行前后及错误事件覆盖SELECT、INSERT、UPDATE、DELETE、批量操作与失败；同时在业务调用区间计量连接申请、fetch及事务调用。

记录db.system、脱敏数据库别名、operation、查询模板指纹、允许的表名、executemany、可可靠获得的影响行数、db_query_ms、连接/事务标识和错误SQLSTATE。SQL模板参数化且限长，参数值、完整连接串及原文禁止记录；未经脱敏的literal SQL也不能原样输出。rowcount未知或-1时保留unknown，不能推断为零。

连接计时用调用申请到实际获得的区间；只在checkout事件打时间不足以证明池排队耗时。遇到延迟自动checkout或共享连接，明确标记计时口径。连接上的请求上下文在checkin、错误和复用时清除，防止A请求的SQL被记到B请求。

### 11.2 事务结果

为每个有写入的业务事务记录begin、flush、commit/rollback及最终结果。commit/rollback的耗时围绕真实调用测量，不能拿通知事件间隔假充。操作日志区分“尝试写入”和“已经提交”；rollback时保留独立技术错误记录，但业务审计不得假称操作成功。

重点验证：原件保存成功但DB失败；DB已提交而云端注册失败；云文件注册成功但检查点失败；笔记发布与索引回写竞争；重复恢复；相同内容并发上传；同会话重复/并发请求；租约续期与过期接管；提交时连接中断。每种故障都检查原件、业务记录、云资源和审计事件是否一致，并说明重试或清理方式。

跨DB、原件存储和云知识库没有天然单事务，不承诺“一次rollback全部恢复”；依靠可重入检查点、幂等和明确补偿达到一致，失败时指出哪个资源已经创建。

### 11.3 慢查询和资源竞争

请求摘要汇总SQL次数、慢SQL次数、查询总时间、连接申请等待和事务时间；观察同接口数据规模增长后的查询次数，定位N+1、全表载入后Python过滤、缺索引及重复轮询。当前列表/范围代码存在载入集合后过滤的路径，需要实测规模影响，不能未经测量就认定一定有性能故障。

对耗时Top SQL在隔离PostgreSQL上结合执行计划、`pg_stat_activity`、wait_event与锁等待核对。`pg_stat_statements`仅在实际允许且可用时使用；不存在则采用应用查询指纹聚合，不为测试擅改生产扩展。`EXPLAIN ANALYZE`会执行语句，写操作只允许在可丢弃测试数据上运行。

数据库监测采集连接数、占用/溢出、长事务、锁等待、死锁、连接失效与池等待；SQLSTATE与异常栈脱敏。不能从单条慢日志直接断言根因，必须附上锁/计划/实例资源等对应证据，或明确原因尚未定位。

## 12 后台任务与检索问答的业务分段

上传记录ingestion_job_id、document_id/version、originating_trace_id、每次worker_attempt、lease/接管状态、排队时间、各云步骤、轮询次数及累计等待。云端轮询每次保留结果，摘要另给轮询次数、首次和最终状态、总等待，不把等待全部算成SQL耗时。

处理进程重启后，为恢复执行创建新trace并链接原job。启动恢复日志标明上次检查点、是否沿用云文件/索引job，不能换一条trace就丢掉原始请求。若需要新增持久字段，先评审迁移、旧版本兼容和回退；没有持久关联就必须标为待完成。

问答至少包含以下阶段：鉴权、范围解析与ACL、会话读取、历史摘要、追问补全、每批云检索、片段筛选与去重、上下文组装、模型连接与首个答案、完整接收、引用校验、再次权限检查、消息保存及提交、最终SSE事件。某阶段未执行要说明skipped原因，而不是消失或显示0ms。

记录selected_document_count、实际批次大小、每批过滤文档集合指纹、命中数、候选/选中片段数、证据版本、截断标记及usage可用性。诊断记录不保存完整提示词、问题、回答或文档片段；必要的详细内容只能存放在脱敏测试证据集中。

文档中的提示词注入只当作待分析内容；历史回答不能当作事实依据；权限撤回后历史摘要、缓存、引用与导出均要复验。跨文件比较要核对实际召回与证据选择，不把“模型正常返回”当作召回正确。

## 13 真实模型与解析质量验收

复用现有 `scripts/manual/evaluate_company_knowledge.py`、`rescore_company_knowledge.py` 和 `report_company_knowledge_quality.py` 前先读参数与副作用；它们的历史评估不能直接作为本轮结果。

至少建立以下金标准分组：

1. 单文件事实抽取，逐条核对数字、单位、年份与对象。
2. 两份以上文件比较及表格，覆盖缺失值、冲突值和不同口径。
3. 资料后半段才出现的答案，确认不只读取前部。
4. 明确选择、目录递归并集、超过20份和跨100份批次的过滤集合。
5. 全库与我的项目、我的经验、仅草稿、空目录的不同范围。
6. 首问后完整新问题与“它/继续/上一问题”追问；包含用户原复现“请把所选资料中明确披露的数据整理成表格”。
7. 无证据、检索被截断、部分文件解析失败，不能装作已经通读完整知识库。
8. 禁止内容或已撤权资料的哨兵字符串，不得出现在候选、上下文、答案、引用和导出。
9. 音视频只有文字说明的资料，答案必须标明据文字说明，不能声称完成自动转写。
10. 两个不同账号并发提问相似问题，确认缓存、历史、来源、watermark与日志不串号。

每组至少2至3个不同样本，关键组重复3次，保存模型名称/版本、参数、资料版本、问题集版本、各阶段耗时及人工评分。真实服务用于正常与代表性边界；精确故障码、重置和超时由受控模拟补充。对随机性记录逐次结果，不能挑最好的一次。

硬性门槛为越权内容零泄漏、引用只能指向本轮允许的资料、关键事实不得编造、上游错误不得伪装无依据；普通表达质量与覆盖率逐条评审。小样本100%不等于长期可靠性100%，不要用单个综合评测分数掩盖关键失败。

## 14 日志保留权限和可用性

请求/错误摘要与详细span分开输出、分开轮转，做到详细7天到期后仍可用摘要排查近30天问题。业务操作审计保留其原有规则，本方案的7/30天不能删除或缩短业务审计、备份和资料保存期限。

每天按实际请求量、平均span数、每条大小和压缩比估算空间：`详细日量 × 7 + 摘要日量 × 30 + 索引及轮转临时空间`，至少预留30%余量。先运行一天量级压测估计，再写入明确容量上限。不能不加限制地打开调试日志，也不能静默缩短用户确认的保留期。

日志目录不在静态网站或资料下载路径下，不进入Git/部署源码包，限制服务与运维账号读取；故障报告与HAR在分享前再次脱敏。普通成员只能取得自己当前错误的支持编号，不能查看全站trace或其他人的日志。

日志写入采用有界队列/批量输出；记录队列深度、丢弃数、导出失败、最早未落盘时间和磁盘剩余量。日志系统故障不无限阻塞业务，也不递归写日志；有受限的stderr回退和可见告警。磁盘满、权限拒绝、写入缓慢、导出服务断开、轮转、保留清理和优雅退出都要实测。

进程被强杀时未结束span可能丢失，因此开始事件和关键检查点要可关联，重启后把无法闭合的记录标记interrupted/unknown，不补造成功。不能保证“任何故障绝不丢日志”，必须实测并报告退出/崩溃的观测边界。

指标维度只用environment、route模板、stage、provider、outcome、error_category等有限集合；不要把trace_id、user_id、doc_id、原始URL作为Prometheus等指标标签，防止高基数膨胀。

告警至少覆盖：连续请求失败、SSE业务失败、上游429/鉴权失败、解析/索引超时、SQL慢/锁等待、持久后台任务卡住、磁盘容量、日志丢弃和导出失败。先用现有日志/运维渠道验证触发；未确定接收平台时保留本地告警事件并将接收方列为发布前确认项，不宣称告警已送达某人。

## 15 性能负载与初始排查阈值

以下为本次拟采用的验收目标与诊断线，不是现有性能承诺。先跑单用户基线，再用相同数据、候选版本和资源执行并发；确因真实模型或文件规模不适用时，拿实测证据调整并请用户确认，不能事后放宽掩盖失败。

| 路径 | 初始目标或诊断线 | 报告要求 |
| --- | --- | --- |
| 本地目录/项目/权限列表 | 热态API p95不超过1秒，p99不超过2秒；不含主动云同步 | 每接口至少100个样本，并报告样本数、p50/p95/p99/max及错误率 |
| 普通元数据写入 | p95不超过1秒，且提交后读取一致 | 包含事务提交；大文件上传和外部解析不混入 |
| 单条SQL | 超过200ms列为慢查询诊断，超过1秒重点定位 | 阈值触发不直接等同业务失败；并列数据规模、锁等待与执行计划 |
| 数据库连接申请 | 超过100ms排查，超过1秒或超时重点阻塞评审 | 区分新建连接、池等待及连接校验 |
| 真实云检索 | p95初始目标5秒以内 | 逐批次和总体壁钟时间；provider内部不可分解部分明确标示 |
| 问答首个有效答案 | 端到端p95目标15秒以内 | 单独报告追问补全、检索、模型首字；heartbeat不算答案 |

| 小文件原件/工作表预览 | 5MiB以下、无复杂图形样本，缓存命中p95目标2秒以内；冷转换单独报告 | 首次转换超过30秒须有可见状态或明确失败/重试策略，不无限加载 |
| 上传与索引 | 接收返回、原件保存、排队、云解析和ready分别报告 | 不给所有格式一个虚假统一秒数；超出配置期限有可解释终态 |
| 观测开销 | 相同负载开关对照，API p95增加不超过10%或20ms的较宽者，CPU/内存/磁盘均有界 | 至少3组交错对照；超出则优化，不直接关闭失败记录 |

在线普通API至少100个样本/关键路线用于分位数；真实云模型每档至少10次成功机会并报告全部失败与取消，低样本p99只作描述不作稳定承诺。每个并发档位10分钟，混合浏览、阅读、搜索、上传、问答，并穿插权限变更。另做一次10个同时发起问答的突发，观察有界排队或明确拒绝。

稳定性观察至少60分钟，以不超过实际10人规模的低强度持续混合操作，监测内存、连接、队列和磁盘走势。限流拒绝作为正常容量保护单独报告，不能同时计入成功吞吐；预期的安全测试403/422也与正常业务失败分开统计。

测试停止条件：隔离资源接近耗尽、错误持续增长或出现无法解释的数据错乱，先停止发压保留证据和现场，不能继续放大。用户额度充足不意味着无限重试或无界负载。

## 20 上线后按编号排查的操作手册

用户报错时收集北京时间、操作页面、错误编号及是否已经看到部分结果；不要求用户发送密码、token或完整私密资料。正常情况下5分钟内应能定位到具体失败阶段及证据；实际演练计时，未定位根因要明确说证据不足。

| 现象 | 先查哪里 | 下一步核对 |
| --- | --- | --- |
| 点操作后没反应 | interaction_id与前端错误、网络请求 | 未发请求则查事件/脚本/校验；已发则查request_id和后端是否收到 |
| 列表慢 | server_request、DB acquire/query/fetch、cloud_sync | 本地过滤数据规模、锁/连接等待、是否错误等待云同步、迟到响应 |
| 文件一直处理中 | document_id/version与持久job、最近检查点 | 排队、租约、OSS、解析/索引、最后轮询、重启接管和实际上游状态 |
| 问答一直等待 | query rewrite、retrieval batch、model_first_answer | 追问补全格式/超时、某批检索、模型首字；heartbeat不能证明模型在生成 |
| 问答中途断了但HTTP200 | SSE outcome与最后业务事件 | 上游断流、引用校验、权限撤回、DB提交、客户端取消；确认部分答案保存状态 |
| 结果或引用错误 | 范围指纹、召回/选中数、证据版本、金标准 | 检索覆盖、上下文截断、不同对象或时期、模型错误；不能仅归因模型 |
| 数据写入显示成功但看不到 | 业务事务、commit/rollback与后续查询 | 是否真的提交、目录/权限过滤、缓存和并发版本；核对审计结果 |
| 偶发超时 | 上游attempt、timeout_stage、pool与资源图 | 外部限流、连接新建、CPU/磁盘、锁等待、并行队列；根据证据归因 |
| 没有完整trace | request摘要、开始事件、导出故障、重启记录 | 日志是否丢弃/过期、实例/版本查错、上下文断裂；标明缺口，不编造链路 |

执行者需实现本地只读trace查询工具：按trace_id/request_id/job_id/时间窗检索，输出树或时间表、最慢阶段、实际重试与错误原因；支持摘要30天与详细7天两种查询结果。支持受限CSV/JSON导出并脱敏，不开放全站日志给普通成员。

执行会话读取本文件和配套清单后，首先给出：

1. 最终准备测试的代码、环境、服务与存储目标，是否与当前线上相同配置。
2. 风险排序、拟修改的观测位置，以及不能用历史测试替代的真实验证。
3. 与其他会话正在进行的改动如何合并、如何固定唯一候选；不覆盖其他未提交工作。
4. 已能独立推进的工作和确实需要用户决定的剩余问题。

随后直接进行授权范围内的基线、隔离与观测建设，不停留在重新写一遍计划。只有影响权限、数据策略、生产切换或确有歧义的业务规则需要提问；现有文档/代码能查到的参数不重复问用户，外部额度充足、隔离环境和7/30天保留不再重复确认。

本方案未指定新的用户可见聊天，也未自动向原会话发送启动消息；用户把TASK.txt交给目标会话后开始任务。
