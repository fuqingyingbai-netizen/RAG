## PDF问题与优化

此文件约5MB、24页。原阅读器需要先取得整张页面图像，再交给浏览器解码；后续页面串行请求，跳到末页时会等待此前正在传输的离屏页面。服务端抽样显示第一页生成约400毫秒、加水印约748毫秒，PNG图像约886KB，浏览器等待中有较大部分来自公网图像传输。

现在通过`Accept: image/webp`请求**无损**预览，服务端保留原分辨率、水印和追踪信息，当前首页图像约541KB；同一身份的PNG/WebP派生图像逐像素比较一致。没有WebP支持或显式拒绝WebP时继续返回PNG。下载和归档原件未改格式，鉴权、渲染后权限复查、版本校验、审计和`private, no-store`仍生效。

跳页会取消离屏请求，目标页优先开始。最终采用单个前台/临近页请求，保留服务端既有两个水印处理槽位；不提高服务器并发上限。页面GET遇到429/503时最多额外重试两次，等待可被关闭/跳页取消，不对上传、审批或结算操作自动重试。页码指示器改为跟随可见面积最大的页，修复末页已出现却仍显示前一页页码的问题。

中间版本的实测曾暴露“浏览器取消请求后，后台水印线程仍在完成，两个预取占满槽位，目标页收到429”的问题。已以收紧预取和有上限的只读等待重试修复；最终真实文件检查中，首页、目录、解析片段和第24页请求均200，末页图像显示且页码框为24，无浏览器脚本错误。
