# 追问校验与引用格式修复

本次只更新 main，不部署、不修改正式模型配置。

## 两个问题如何处理

1. **追问补全未通过校验**：保留对象、字段和用户限制的原有校验；仅对结构或意图校验失败自动纠正一次，将失败输出及校验原因交给模型重新生成。仍失败则明确报错并保留待确认状态，不回到旧对象。403、429、连接失败不作为格式问题重试。首次真实失败的原始补全文本未保存，具体失败字段仍未定位；本次修复是对失败流程加固，不能声称已找到了当时的具体根因。
2. **引用写成 `[3]`**：加强模型的标准引用要求，并在回答展示及保存之前，将正文中可确认的本轮来源编号规范为 `[id_3]`。代码、链接、公式、数组及数值示例保留原样；不能确认的形式不猜测映射。遇到可识别的未知来源编号时，不按成功回答保存。屏幕、历史和导出都使用同一份规范后的回答。这只修复格式，不证明每个业务结论的来源归因都正确。

引用处理按行缓冲，跨模型分片的编号可完整识别；多行回答仍逐行返回，单个长行可能到换行或生成结束后才展示，处理中状态和心跳继续保留。
