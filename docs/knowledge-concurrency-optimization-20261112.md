# 公司知识库并发优化（2026-11-12）

本轮在已有第 1～10 项未提交修复的完整快照上实施，业务基线提交为 `74b705f`。只优化知识库；账号管理、报告模型配置与生产数据库未改动。

## 实现

1. **数据库连接生命周期**：知识库使用独立的短会话鉴权，保留停用、归档、令牌版本与强制改密检查；返回已加载的账号对象后关闭会话。问答范围读取、会话创建、上下文权限复查及答案保存，在工作线程中创建并关闭自己的数据库会话，不在线程之间传递 Session。浏览和选定范围问答移除重复历史回填，历史回填保留在启动迁移及云目录导入阶段。选定资料时在 SQL 中按 ID 限定查询，继续逐项执行原有 ACL 和资料库范围检查。
2. **接入保护**：单进程同时接入最多 10 个问答响应、3 个上传/补传原件请求。上传另有最多 7 个等待位置、最多等待 5 秒；队列满或等待超时，在读取上传请求体前返回 503 和 `Retry-After: 2`。普通浏览不占这些额度。锁冲突仍按原有规则返回 409，不自动重放写入。原有后台索引的 3 路限制保持。
3. **模型额度**：摘要、追问改写和正式回答通过同一个进程级额度，默认同时 3 路，最多 7 个等待者，按到达顺序处理，默认最多等待 60 秒。SSE 告知排队，超时或队列满明确失败。取消、异常、重试和流结束都归还额度。仅响应头在 5 秒内返回的 502/503/504 可重试一次；响应头已等待 5 秒及以上的失败、429、已输出但中断的回答均不重放。
4. **首答和追问**：普通正文前缀在换行前即可输出；从引用、代码或公式标记开始的行尾继续保守缓存，保留既有 Markdown 和引用校验。仅完整、明确的单项目模板和短字段追问走本地补全，保留年份等范围约束；旧指标的回答格式不带入新指标，当前明确的输出要求优先。多对象和不确定意图继续交给原有模型改写。改写排队失败也将任务标为待澄清，避免下一轮误用旧对象。GLM 参数分支不再为判断其他供应商选项而冷加载报告模型库，模型及其推理参数未变。
5. **观测和中断清理**：沿用现有不记录正文、密钥和 SQL 的限量日志，增加数据库借还次数与持有时长、模型排队、上游响应头及内容可用时间、应用首个答案增量、上下文准备和追问改写耗时。显式关闭每层流式迭代器，并保护断连后的短清理事务，避免取消请求留下正在回答的租约。

## 配置与边界

- `COMPANY_KNOWLEDGE_MODEL_CONCURRENCY`：默认 `3`，必须大于零。
- `COMPANY_KNOWLEDGE_MODEL_WAIT_SECONDS`：默认 `60`，范围大于零且不超过 60 秒。等待时间计入请求耗时；回答阶段原有 180 秒总预算、追问/摘要原有 90 秒总预算仍然生效，排队不会无限延长阶段预算。已有环境变量覆盖值优先，发布前需核对生效配置。
- 当前部署文件 `deploy/supermew.service` 使用 `--workers 1`。额度按进程计算；增加 worker 前必须按上游总额度重新核算，不能把每进程的 3 路当作跨进程总额。
- 不扩大数据库连接池，不引入 Redis/队列服务，不改变模型供应商或密钥，不修改数据表结构，不缓存答案和权限结果。
- 有限排队及明确拒绝只能证明保护有效，不能视作 10 人问答或上传成功率达标。上游即使在单路时也可能慢，首答和完成目标必须分别按成功率及全量样本核验。
- 本地选择范围之外的字段、引用和历史权限复查保留；普通文字提前显示不表示通过最终引用检查，必须收到 `saved` 和 `done` 才算完成。

## 验证记录

最终验收工件位于 `work/acceptance-20261112/`，最终结果以该目录的报告为准。主工作区已有修复的原始文件哈希位于 `work/optimization-baseline/manifest.json`。初次真实断连检查暴露了异步清理取消问题，失败记录保留在 `preliminary-v1/`、`preliminary-v2/`，不计为最终通过。

后续网关专项诊断与策略调整在 `work/gateway-diagnosis-20261112/`，前述验收目录保持封存。已只读核实线上知识库模型为 `glm-5.3-flash`，本机 `.env` 中的 `glm-5.2` 与线上不同，不作为此次发布的模型切换依据。生产服务器和本机的同模型、同密钥单请求及供应商公开备用入口均出现上游 502；官方账号查询显示有效且有剩余调用次数，但不提供并发/RPM/TPM。一次后续真实应用请求成功，首答约 65 秒，其中约 48 秒等待网关响应头，不能据此认定已恢复稳定。3 路是保留的应用保护配置，不是已确认的供应商并发额度；60 秒是排队上限，不是答案时延承诺。5 秒重试门槛用于避免把已等待 40～57 秒的故障请求再执行一次，不代表供应商 SLA。

追加探测捕获网关 HTTP200 响应体中的 `rate_limit_error`，原文提示账号并发额度超限；只有一路本轮真实请求时也发生，限制可能涉及共享密钥或供应商上游账号池，当前证据无法区分。流式回答与非流式追问/摘要现统一把这种错误分类为 429，丢弃供应商错误原文，保持不重放、不保存为完成的行为；外部 HTTP 实测确认原会话随后可恢复。3 路直接探测仅成功 1/6，未扩大到 5 路；供应商容量仍未通过验收。

最终代码须通过单连接池鉴权、队列超时及取消、真实 HTTP 生成中断连和排队取消、同会话恢复、引用分片、账号权限、原件/版本一致性、模拟限流/中断、真实模型 1/3/5/10 人混合负载及 60 分钟观察。合成 TXT 的结果不能外推到大量 Office/OCR 文件、生产资料规模或多 worker 部署。
