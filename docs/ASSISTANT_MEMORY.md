# 小助手的账号记忆

聊天记录保存在服务端数据库，按登录用户的 ID 隔离，管理员也不能通过小助手接口读取其他人的会话。更换浏览器或电脑后，登录同一账号、连接同一套后端数据库即可恢复。浏览器不再长期保存新版对话正文。该记忆仅供小助手续聊，不进入公司知识库或研究溯源库，也不代表模型经过了个人数据训练。

## 保存、切换与删除

- 每条用户消息先入库，再生成回答；回答和联网引用成功入库后，页面才显示“已保存到账号”。刷新时可以恢复，异常中断的消息会标注回答已中断。
- “新对话”创建空的上下文，旧对话仍然保留，可以在会话选择框中切换回来。选择框展示最近创建的100个会话。
- 页面每次加载最近80条消息，“加载更早消息”继续分页读取。这里是展示分页，不会删除旧消息。
- 退出登录会中止当前浏览器请求、清空页面状态，保留服务器记录。关闭悬浮窗或切换系统页面不会重置上下文。
- “清空记录”经页面确认后删除当前账号全部小助手消息、引用和摘要，并开始空会话；公司知识库资料不受影响。当前没有按天过期。数据库运营备份有各自的保留策略，应用删除不等于擦除已有备份。
- 新版第一次加载时，可将旧浏览器中现存的最近80条消息及旧摘要迁移一次；旧版已经丢失的消息无法恢复。迁移成功后移除旧缓存。已有服务端历史不会被另一浏览器的旧缓存覆盖，清空后也不能通过旧缓存自动恢复。

## 如何压缩

每次回答前，后端从当前账号、当前会话读取历史，不信任浏览器提交的历史替代内容。

当“旧摘要 + 尚未摘要的消息”超过 **12000个字符**，或者尚未摘要的消息超过 **40条**，尝试调用当前聊天模型整理较早消息。这里使用保守的字符预算，不是精确的 token 计数，也不是固定第几轮。

压缩时优先保留最新12条消息，受约7000字符预算约束；其余较早消息每批最多24000字符，合并旧摘要，请模型提取用户明确的事实、偏好、目标、约束、指代和待办。新摘要最多3000字符，避免把助手猜测写成用户事实，并保留动态事实的原日期。摘要作为不可信的历史资料传给模型，不能覆盖系统指令。

普通回答使用最多12000字符的“摘要 + 最近消息”；系统说明和当前问题另计。超长单条消息可能只放入开头和结尾并注明省略，原文仍然保留。每次压缩推进一个已总结位置，避免重复处理全部旧记录。摘要失败、超长或超时时不推进位置，保留原文，提示“当前仅参考部分历史”，下次请求重试。摘要仍可能遗漏细节，不能保证模型永久精确记住每句话。

## 并发与恢复

同一会话一次只允许一个回答任务，通过数据库条件更新领取180秒租约，适用于多个浏览器标签页和多个服务进程。重复的请求ID会被拒绝。服务崩溃后租约会到期，后续请求可继续；被打断的旧消息不会伪装成已完成回答。

浏览器用请求代次隔离退出登录、切换和清空操作，旧响应不能填入新的页面会话。数据库保存也必须匹配租约；会话被清空后，后台迟到的回答或摘要不能重建它。模型和摘要任务均有超时，SSE 每3秒发送心跳，总等待120秒，浏览器135秒超时。

## 代码和验证入口

- `backend/models.py`：独立的 `assistant_states`、`assistant_threads`、`assistant_messages` 三张表。服务启动通过现有 `init_db()` 创建新增表，不改动已有业务表字段。
- `backend/assistant_memory.py`：账号归属、分页、迁移、数据库租约、上下文预算和 AI 摘要。
- `backend/research_api.py`：会话管理接口、流式回答与持久化。
- `frontend/script.js`、`frontend/index.html`：账号恢复、会话切换、清空确认、同步状态和过期响应隔离。
- `test/test_assistant_memory.py`、`test/system-guide-ui.test.cjs`：隔离、恢复、压缩、失败、分页、迁移和并发回归。
