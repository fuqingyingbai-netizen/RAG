# 行业质量验收集候选 v1

这是可运行、版本固定的第一版候选验收集，尚未经过业务人员确认。期望结果由助手依据验收准则先行指定，不调用生产校验器生成标签，也不把基线的输出反写为答案。

## 包含什么

公开部分位于 `test/fixtures/industry_acceptance/v1/`：

- 30条固定样例，15条预期放行、15条预期拦截，覆盖15类问题。
- 22条开发对照，8条固定改写挑战样例。挑战样例在创建时已经可见，不能宣称为统计意义上的独立盲测集。
- 材料涉及机器人、人工智能、新能源汽车、光伏和半导体。所有正文、数字、法规条款均为合成材料，不是对真实行业或法律事实的认定。URL仅用于检查来源角色，绝不请求原站。
- 每条包含来源正文、候选事实或陈述、研究范围、检查入口、固定期望、判断依据和分组；数值、期间和错误类型等附加标签也独立核对。
- `manifest.json`固定样例文件SHA256；修改原文或标签时须记录理由并发布新版本，不能为了提高通过率覆盖v1。

15类问题包括指标与单位、预测与实际、企业样本、政策目的与义务、建议与经营兑现、保存正文定位、同句多指标、独立来源、缺证与风险、企业数与集中度、增速类型、负号、发布时间与统计期、技术主张与实测、局部测试外推。

私有部分位于忽略的 `work/industry-acceptance-20261023/`，固定6组已保存报告及建议书的输入路径、原始文件指纹和业务复核清单，不复制或改写历史产物。其中包括原有网络故障的历史运行，不能把其保底产物当成模型成功。6组均来自同一人工智能行业项目，不是6个独立行业，也不是当前代码重新生成的6组报告。

## 怎么运行

在项目根目录使用项目Python：

```powershell
# 快速评测固定样例，不运行研究、pytest或历史回放
.venv\Scripts\python.exe scripts/check_industry.py --acceptance-only

# 保存新结果；使用新的文件名，避免覆盖既有证据
.venv\Scripts\python.exe scripts/check_industry.py --acceptance-only --acceptance-output work/industry-acceptance-20261023/check-02.json

# 生成便于阅读的HTML，且核对私有历史输入指纹
.venv\Scripts\python.exe scripts/industry_acceptance.py --private-manifest work/industry-acceptance-20261023/historical-manifest-v1.json --output work/industry-acceptance-20261023/check-03.json --review-output work/industry-acceptance-20261023/review-03.html

# 先运行行业全量回归，再运行固定样例
.venv\Scripts\python.exe scripts/check_industry.py --full --acceptance
```

评测期间阻断网络，既不调用模型或搜索，也不导入业务数据库或触发研究。默认不输出私有历史正文。生成JSON和HTML只能写入私有 `work/`，不能覆盖输入、历史产物或已有评测结果。

退出码：0表示所选固定标签全部匹配且所选输入指纹一致；2表示存在候选标签差异或历史文件指纹不符；1表示输入或运行错误。差异不等于历史研究任务失败，也不等于候选标签已经过业务确认。

## 如何读结果

JSON按类别和分组报告：符合标签数、误放行数、误拒绝数、运行异常数，以及每条的预期、实际和差异。

- **误放行**：预期拦截，现有规则却放行。
- **误拒绝**：预期放行，现有规则却拦截。必须和误放行一起查看，不能靠全部拒绝改善指标。
- **运行异常**：没有得到有效判断，不能算作拦截成功；某一类没有有效样例时，比率为null，不是0。
- 布尔判断匹配但期间、归属或错误类型不符时，该条仍不通过。
- 这是既有确定性闸门的评测，不是完整语义证明、模型新输出质量、风险概率校准或Word版式验收。

创建时的首轮基线为29/30，15条正确对照全部保留、0误拒绝；`IA-029`暴露了单厂商单配置测试外推为全行业技术成熟的误放行。该预期保持拦截，不改标签来适配当前规则。基线结果和差异详情保存在私有输出中。

## 业务复核流程

1. 先看HTML中的来源正文、候选陈述与判断依据，不仅看系统判断。对30条期望逐条确认或提出更正。
2. 对6组真实报告，逐条标注摘要和关键结论的支持程度、统计范围、章节分析价值、重复、技术比较、风险状态和建议书任务一致性。文件指纹及章节数通过不算业务质量通过，待复核项始终保留null。
3. 更正应包含样例ID、原标签、新标签、依据、复核人和时间。存在争议时记录待裁定，不借系统输出决定标准答案；新标签另建版本，保留原基线。
4. 后续增加未参与开发的独立材料，保持正反对照；只有经独立业务复核后才能称人工确认的验收集。
5. 一组代码修改后先运行固定样例及已有回归，再在授权的新研究中验证真实模型表现。离线评测通过不能替代该步骤。

验收工具自身的回归见 `test/test_industry_acceptance_dataset.py`，覆盖全部放行/全部拒绝不能通过、额外标签、错误分母、网络阻断、输入不变、历史指纹、隐私输出、HTML转义及退出码。它验证评测工具正确工作，不表示所有候选业务样例都已经通过。
