# 行业证据改造：第一阶段

本阶段落实优先级最高的指标驱动检索和结论证据关系，同时隔离静态演示数据。核心契约放在独立、无数据库与模型依赖的`backend/industry_evidence.py`，供检索、清洗、章节选择、交付与离线测试共用。

## 已接入的流程

1. **研究问题先行。** 计划按启用模块列出规模、增长、集中度、份额、收费机制、盈利质量、技术成本、政策与可选资本证据要求。未启用资本不产生资本缺口。每项要求包含问题、可接受层级和补采词。
2. **区分候选与核验。** 检索阶段只看保存正文里的指标候选；标题、摘要、企业样本和“未披露”不能充当行业指标证据。来源条数与候选覆盖分别记录。集中度座谈会不等于CR3数据。
3. **只补缺口。** 已有来源满足模块数量时，优先复用来源，仅对指标缺口补采；继续受原查询轮数、查询预算与跨轮去重限制。清洗后仍不足的指标保留明确缺口，不用更多材料条数代替指标回答。
4. **保存原文定位。** 每张事实记录来源ID、原始对象地址、正文SHA256、字符起止位置和对应原文。PDF排版空格与大小写可归一匹配，返回位置仍指向原始正文。摘要专用内容、解析失败占位符与伪造引文无法取得有效定位。
5. **隔离不成立的证据。** 行业快速摘录改为只从保存正文截取，去掉摘要优先与人为截断标记。不能定位的事实保留在审计数据中，但不进入写作和评分。平台结构化快照也可定位，企业样本边界不会因此被升级成行业证据。
6. **按指标和文档选证。** 在现有模块、结构化程度、数值质量排序基础上，为未覆盖的完整指标及不同文档留出位置；每章卡数和提示预算保持有界。章节提示同时提供研究问题的覆盖状态。
7. **保存结论证据台账。** 新增可下载的`industry_claim_ledger` JSON成果，关联清洗、评分、报告的产物ID与正文指纹，并列出正文位置、声明编号、事实引用、原文定位和确定性检查结果。续跑重导出生成对应新报告的台账，不能拿旧台账证明新正文。未定位的引用进入复核原因。
8. **缓存看实际输入。** 清洗复用增加正文、文档身份和研究边界指纹；重复来源行、仅搜索摘要变化不触发无效重算。评分及报告分别核对上游产物ID和正文指纹。补采或修订上游后不能沿用旧下游。

清洗版本为`industry-evidence-v9-local-nature`，报告为`industry-report-evidence-v17-validated-fallback`，风险规则为`industry-risk-v5-diverse-evidence`；新事实使派生评分重新生成。

第七轮发现历史值和预测值共处一段时，规则提取会错误继承后续“预计”，而摘录保底仍复制多指标原文。现在按指标紧随数值所在分句及紧随括号标记识别预测属性；短预测引导语可延续到下一分句，不能跨其他数值借用。已定位模型卡同样校正，再生成事实编号。它是确定性文本规则，不代表来源数据已被独立验证。

保底改用单卡完整数值口径与预测标记，不把整段其他数值借入。保底自身也经过数值标记和语义检查，不能安全转述的内容只保留引用及复核提示；摘要按完整卡片取舍，不从数字或单位中间截断。评分证据在模块平衡基础上优先覆盖完整指标、不同文档和实际统计，不能因多卡就声称独立印证。竞争与成本证据仍可能真实缺失，不能通过选证改造强行补分。

## 如何解释核验状态

- `missing`：没有满足要求的证据候选。
- `candidate`：有相关材料，但没有满足原文定位、范围和指标口径的完整事实。
- `verified`：至少一张事实通过本契约的结构化检查；不代表指标覆盖所有年份，也不代表不同来源已经独立印证。
- `references_verified`：该条声明的引用、原文定位与确定性数值/属性检查通过。**不代表原文充分支持整句结论**；`entailment_status`始终明确为`not_evaluated`，推论仍需人工复核。

定位的字符偏移针对`research_sources.content`，不是PDF字节位置。对象地址用于回查原文件；正文哈希用于识别后续修改，不把数据库可变记录误称为不可变档案。检索正文窗口与词汇规则属于候选筛查，不构成完整语言理解。HHI等暂无完整数值单位支持的数据可以保留候选，不能冒充通过指标校验。

## 验证与兼容

新增小型合成标注集`test/fixtures/industry_evidence_cases.json`，覆盖座谈会、真实集中度、未披露份额、企业样本、搜索摘要和规模增长。另有原文偏移、正文指纹、摘要污染、平台快照、指标选证、局部补采、版本依赖、重导出台账和演示隔离测试。使用`scripts/check_industry.py --full`；保存产物回放还会检查台账与原报告、事实及评分的指纹和产物ID是否相符。

静态追溯接口默认关闭，只有`RESEARCH_DEMO_ENABLED=true`时启用，返回明确的`is_demo`与`data_origin`标记；研究助手也不会默认命中演示回复。真实项目读取路径继续使用原权限检查。

本阶段不迁移数据库表，不改变公司、人物线路的检索与清洗语义。新增的成果类型、演示开关及下载格式是共享API兼容扩展。

## 后续阶段的接口边界

运行持久化的第一步已接入`backend/industry_runs.py`：每次行业执行新建独立UUID与`industry_run` JSON产物，记录父运行、阶段起止、完成/暂停/失败、产物ID/版本/内容哈希、复用或新建及输入依赖。记录直接存于现有成果表，阶段边界在工作流主线程提交；模型线程只汇总有界事件计数，不共用数据库会话。下载读取数据库最新记录，不依赖对象存储中的初始副本；新运行不修改旧运行清单。

流式日志携带run_id/run_started_at，各轮使用不同成果行与对象地址，保留旧日志；迟到的旧运行或无运行编号快照不能覆盖新运行。阶段复用的旧产物保留其原始身份，新产物带本次run_id；运行清单明确区分引用复用与新建/重导出。实时进度轮询只读取最新行业日志，不反复下载全部历史正文。公司和人物执行继续走原流程。

**执行器仍是进程内线程，没有持久化任务队列、分布式租约或服务重启后自动续跑。** 记录中的running表示最后保存状态，worker_liveness明确not_verified，不能据此认定工作线程仍存活。阶段开始时间是现有粗粒度检查点边界，暂停会保留下一待执行阶段；记录完成也不表示报告已通过质量验收。服务重启后可以回查最后阶段和版本依赖，但恢复仍需用户显式继续，并经现有版本/指纹规则核验缓存。数据库不可用时只能保留上次成功提交的检查点；流式日志继续受既有事件上限约束，截断标记保持可见。

风险校准的准备层已接入独立的`backend/industry_risk.py`：使用版本化等级锚点和各维度判断要点，初次评分和一次局部修复使用同一口径。风险输出、报告元数据、页面及质量诊断分别呈现风险分、指标覆盖和“尚未校准”的评分可信度。覆盖仅统计实际进入预算内评分包的适用事实；来源摘录、企业样本、无法定位的事实不能变成完整指标。被模型主动弃评的维度可以有证据覆盖，但风险分仍为空；局部修复后刷新统计。文档数不等于独立来源数，预测数值单独计数。

等级区间沿用既有风险等级，维度内分值仍为模型判断；总分仍是全部启用维度完成后的等权均值。**尚无人工标注样本和分值权重校准，不输出可信度概率，也不宣称评分已校准或判断已被原文蕴含。** 模型不能自行覆盖服务端生成的证据统计和校准状态。写作只收到评分限制说明，不把覆盖计数当行业事实。旧产物保持历史状态，只有下次用户主动研究或续跑才按新版本生成评分与报告。

| 阶段 | 改造内容 | 验收重点 |
| --- | --- | --- |
| 风险校准 | 等级口径和分开展示已接入；后续补人工业务样例、权重和分值一致性评测 | 人工标注的一致性，不以引用合法替代评分合理 |
| 运行持久化 | 独立运行ID与阶段清单已落库；继续接入持久化任务队列、租约和幂等重试 | 服务重启、多个worker、只重试失败阶段、历史运行不覆盖 |
| 共享工作流拆分 | 将阶段执行、模型调用、存储导出与三条路线策略拆为明确接口 | 三条路线契约和兼容测试，逐阶段迁移 |
| 持续质量评测 | 扩展有人工标签的真实案例集，记录准确性、遗漏、波动、耗时与成本 | 真实模型多次结果，固定输入与版本对照 |

上述阶段涉及业务评价标准或三条线路共享基础设施，不能把本阶段的确定性契约测试当成已经完成这些改造。现有内存线程运行方式仍需后续替换；本阶段的产物依赖记录为后续运行模型提供可迁移的输入边界。
