# 本地后台启动与模型连通性

Windows本地后台应从正常PowerShell终端启动。在受限工具进程内启动的后台可能继承外网限制：本地页面和数据库可访问，远程模型却返回连接失败。请勿仅凭首页200判断模型网络正常。

先执行无密钥连通性检查：

```powershell
.\.venv\Scripts\python.exe scripts\run_backend.py --check-only
```

检查只向配置的模型服务发送一次不带鉴权的GET `/models`。401等HTTP响应表示网络可达，不代表密钥有效、模型存在或生成请求成功；不会请求生成内容、搜索或收费研究。Windows套接字10013会明确报告为`network_permission_denied`，不输出异常原文、密钥或带鉴权的URL。

端口空闲时启动：

```powershell
.\.venv\Scripts\python.exe scripts\run_backend.py
```

已有服务时，应先核对`/version`实例、准确监听进程与可执行文件，以及研究任务和知识库导入均空闲，再重载。不得用此命令重复启动或覆盖尚在执行的任务。启动器会在同一启动环境重新检查模型网络，连通性失败时不启动后台。

研究调用失败后仍可保存原文与规则整理结果，流程完成不代表模型分析完成。没有有效分析的章节应明确写未形成综合结论；不能把提示语或缺口说明包装成已经完成的分析。行业文档在未作可靠分页验收时，目录保留可点击章名，不输出未计算的页码。

检索凭据写入被Git忽略的本地`.env`。`EXA_API_KEY`使用真实API密钥；`TAVILY_API_KEY`保留单密钥兼容，`TAVILY_API_KEYS`可用逗号分隔备用密钥，程序先主后备并去重。仅额度耗尽、无效鉴权或访问拒绝才切换下一把，并在当前进程跳过已失效项；超时、429限流和参数错误不轮换。每次成功检索只用一把密钥，不为测试轮换而重复发出成功查询。密钥只发送至对应供应商API，审计只记录尝试次数，不记录密钥。

兑换码不是`BOCHA_API_KEY`，须先在所属账号完成兑换并取得真实API密钥，不能直接填入鉴权字段。更新`.env`后，确认研究及知识库导入空闲再加载后台；原进程中的失效凭据缓存会随重载清空。配置和模拟测试通过不等于供应商余额、鉴权或真实检索已经验证，未执行真实查询时应说明这一限制。
