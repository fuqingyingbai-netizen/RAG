# 系统使用指南的维护

小助手以本地维护的产品说明回答系统使用问题，不检索用户项目/公司知识库，不把操作问题发到公开搜索服务。普通聊天、写作和外部实时信息能力继续保留。

## 一份目录，两个入口

`backend/guide_catalog.json` 是运行时说明和 [完整用户指南](SYSTEM_USER_GUIDE.md) 的共同来源。每个主题包含标题、页面、自然语言别名、可选的多条件匹配词、详细步骤、适用角色，以及维护者核对代码用的文件和锚点。代码位置不放进普通用户的操作答复。

精确的功能名称、常见问题和当前页面帮助可直接回答，模型不可用时仍能使用。问法复杂时，提示词提供全目录和相关主题，模型可调用本地 `search_system_guide` 补查同义问题。对识别出的系统使用问题只绑定本地指南工具；即使模型仍返回公开搜索调用，执行层也会拒绝。没有收录的功能要询问具体页面或按钮，不能保证回答任意未实现功能。

模型只负责定位主题，返回的操作说明由后端从维护目录直接排版，不使用后续自由生成的步骤。复杂系统问题要求先调用本地指南工具；客户端不支持工具或模型拒绝调用时，回到本地候选查找与澄清。近似匹配会明确标注“可能相关”，不会把猜测说成已实现的按钮。这会牺牲部分自由改写能力，用于保证产品入口和限制不被模型随意改动。

系统帮助按角色过滤管理员专属步骤；普通用户仍能得到注册、找管理员处理或申请文件权限等公开说明。小助手不能代提交任务、删除文件、修改账号或审批，也不声称知道某个真实项目当前的状态。

## 功能变更后怎么更新

1. 拉取最新 main，检查新增或修改的页面、按钮、表单字段、角色权限、后端校验和失败提示；不能仅凭按钮名字推断行为。
2. 在目录更新对应主题。写明入口、操作步骤、前提、状态、可恢复方式和实际限制；增加用户可能使用的同义问法。修改 `reviewed_base` 为本次核对的主分支基线。
3. 用代码锚点记录依据。特别核对前端开关是否被后端固定策略覆盖、上传成功是否还需索引、管理员与上传者/项目创建人的权限是否相同。
4. 重新生成用户指南，运行相关回归和浏览器检查，再集成最新主分支。主分支再有变化时检查受影响主题。

5. 同时更新目录中的 `product_release` 说明版本、核对日期及已实现的变更；这与研究模型版本、报告历史版本不同。小助手“本次更新”读取这份已部署目录，后端部署标识从启动时的 release-manifest 读取，不依据历史聊天猜版本。不要只在聊天提示词里写更新内容。

## 当前目录与顶层入口

前端通过知识库组件的 `assistantHelpContext()` 提供当前模式、弹窗种类和项目/目录/笔记ID，不上传编辑器正文、项目说明或手填路径。后端 `assistant_product_context.resolve_location` 按登录账号、知识库资格、索引和项目权限只读核对名称，子目录必须属于同一项目；已打开笔记使用笔记真实归档字段，避免后台页面位置与笔记位置不一致。无权限或无效ID不返回名称、不猜保存结果。只解释位置和用法，不替用户上传、保存、发布或执行操作。

必须保留三种入口的差异：“上传文件”使用当前目录；本人可管理的经验项目中“新建图文笔记”使用当前目录，其他位置回到自己的待整理项目；“随手记录”固定进入自己的待整理项目。变更任何入口时须同步操作说明与位置回归。小助手通过 Vue Teleport 独立置于 body 顶层；只有浮动入口或面板可接收点击，透明全屏层不能挡住业务页面，且须验证打开笔记弹窗时助手仍可输入、关闭助手不丢失草稿。

测试会核对现有页面是否都有指南、代码锚点是否仍存在、生成文档是否同步，以及具体问题匹配、权限过滤、不会向外搜索、聊天兼容和未知功能处理。测试不能自动判断所有新按钮的业务含义，新增功能仍需维护者读代码后补充，不能承诺指南随任何代码变化自动完善。

## 这次核对的重要边界

- 自动归档的桌面报告默认待复核且限制访问，报告已生成与公司知识库索引完成分开；不是默认向全公司公开。
- 公司研究第一阶段后端固定策略会开启公开搜索；人物/行业可传入搜索开关。专业平台和OCR受独立策略控制，不能把界面开关视为全部网络请求的总开关。本次如实记录该现状，没有更改研究策略。
- 复核流程建议由任务创建人本人完成，但后端也允许管理员管理其他用户项目。不能把流程建议错误描述成后端禁止管理员操作。
- 溯源库入口当前最多加载50条记录，本地翻页不会额外取全量；记录没有展示不等于不存在来源。
- 知识库问答的页面状态、浏览器收藏/阅读记录，与小助手的服务器账号会话是不同的保存机制。
