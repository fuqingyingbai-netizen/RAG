# 知识荣誉积分

积分只用于参与荣誉、等级和排行榜，不兑换、不转让、不影响文档权限，不代表专业资质或绩效。资料库与经验沉淀继续分别展示和检索，积分按账号汇总。

## 员工使用

个人首页积分卡每15秒自动更新，首页刷新按钮也会刷新积分。点击“我的知识积分”，或从左下角账号菜单进入“我的积分”。四个页签为积分概览、积分明细、排行榜、积分规则。积分保存在服务端，换设备后仍可查询。个人只能查看自己的明细；他人只公开账号、等级及积分汇总，不公开管理员姓名备注、阅读清单、文件标题。

默认规则：有效阅读他人的内部共享文本资料 +2，每天最多5份；新文件成功入库 +10，每天最多3份，不受资料授权范围和保密等级限制，奖励实际上传人，管理员代上传也归操作管理员；新笔记首次成功发布入库 +15，每天最多2篇。每天自动奖励最多70分，按北京时间计算；这里是上限而非员工必须完成的任务。等级为0初识、100探索、300同行、800共建、2000领航。周榜从周一开始，月榜从每月1日开始，同分并列。

阅读需要成功交付过预览，页面前台累计30秒且有正文交互。分页、原件与片段切换不独立计分，同资料同一天只有一次。同账号只保留一个活动计分会话，另一个设备开始计分会关闭旧会话；隐藏、失焦、大段心跳空白不累计。会话跨北京时间零点后需要重新打开资料。前台时长只是参与近似，无法证明真正理解内容，也不能完全杜绝模拟浏览器操作。

上传请求成功不立即入账；索引达到ready后，后台通常在下一次约5秒处理周期内结算。处理进度、结算失败及未获奖励原因显示在个人概览。额度用首次达到条件的业务日期检查，不因故障重试重新领取。重复内容、后续文件版本、补传、移动、回收站恢复不重复奖励；首次发布的笔记及生成文件只奖励一次。上传奖励不再受资料权限限制；阅读与笔记奖励仍限内部共享文本资料，音视频暂不参加自动奖励。计分不扩大任何原有资料权限。

已有资料不追溯历史积分；上线后有效阅读旧资料可获得阅读积分，但重新上传启用前已有的同内容文件不会成为新贡献。正常整理、删除不扣分。误发奖励由管理员新增纠正记录，原流水保留。

## 管理员使用

账号管理中的“积分管理”提供人员积分、积分流水、规则设置、结算与异常四个页签。可排除测试账号、恢复参与、补发积分、撤回原奖励、安排失败事件重试。管理员默认不参加员工榜单，暂停参与的账号保留历史积分但停止新增奖励、退出排行榜。停用和归档账号也不参榜。

常规规则次日北京时间零点生效；保存新计划会取消尚未生效的旧计划，历史版本继续保留。紧急暂停只立即关闭奖励，沿用当前分值并取消待生效计划。新规则不重新计算历史奖励。并发修改用版本号拒绝覆盖。

积分补发需要管理员密码二次确认，不允许自行调整本人积分；每次提交有独立请求编号，网络异常重试保留同一编号和内容。撤回须完整对应本账号的一笔正向奖励，同一奖励只能撤回一次；撤回计入原业务周期，不清空原始记录，也不释放当天已使用的奖励次数。

## 实现与隔离

- company_points.py：独立积分表、版本规则、账号互斥写入、账本、阅读会话、后台结算与补偿扫描。
- company_points_api.py：个人接口、管理接口、参数验证、权限和数据库故障降级。
- knowledge-points.js / css：独立页面、首页入口、管理组件及阅读器mix-in。请求代次、账号标识和销毁检查拒绝迟到响应或迟到写请求。
- 入库仅在ready检查点接入；积分捕获失败回滚自己的保存点，不回滚文档状态。后台补偿扫描只读取启用后创建的ready资料，不调用模型或外部检索。
- 积分总分是账本汇总缓存，每笔发放与总分更新在同一事务内完成。账号行写锁及唯一键共同限制并发和重复事件，SQLite与PostgreSQL均有测试。
- 原始阅读会话按过期30天分批清理；积分流水和规则版本独立长期保留，不跟随账号或知识库的短期日志清理。

初始化仅新建积分表及默认规则，不修改用户、资料或会话表结构。默认规则的首次生效时间保存在数据库，重启不重置。首次发布需要后端重启。启动时积分初始化失败会记录错误并保持其他功能启动；积分读写数据库错误返回独立503。

首次启用前应备份数据库；恢复时数据库和资料仍按原运维策略一起处理。源码回退不删除积分表。重新启用后保留同一数据库和事件唯一键，避免补偿重复记账。补偿扫描在捕获失败时使用目录最后更新时间恢复事件时点，因此极端情况下的跨日归属需结合业务日志人工核对，不能把荣誉账本作为财务账本。

## 构建与验证

从最终整合版本运行：

```powershell
python scripts/build-points-assets.py
python -m pytest test/test_company_points.py -q
node --test test/knowledge-points.test.cjs
python -m pytest test/test_company_points_browser.py -q
python scripts/check-points-postgres.py
```

最后一项只使用已有postgres:15镜像，新建并销毁独立、仅绑定回环地址的测试容器；使用专属schema并逐例清空数据，不读取项目.env或连接业务数据库。数据放在容器的临时内存文件系统中，验证真实SQL事务与并发，不声称验证磁盘断电恢复。浏览器验证使用虚构账号和隔离数据库，通过本机Edge与真实Vue/Element Plus运行，不使用真实供应商服务。

不要用旧版仅知识库前端发布器单独发布本功能：必须同时交付新增积分脚本、样式、入口、账号和首页组件、主脚本及后端文件。构建保留旧哈希资源，避免破坏已打开页面。部署应保留当前生产中其他叠加改动，不能直接用旧工作区整包覆盖。
